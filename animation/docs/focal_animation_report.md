# focal 추종 탑뷰 애니메이션 구축 (NGSIM / highD)

작업일: 2026-08-19 · 위치: `Argoverse2study/animation/`

---

## 1. 목적

- Argoverse 2에서 쓰던 **focal agent** 개념을 고속도로 궤적 데이터셋(NGSIM / highD)으로 옮김
- focal 차량 한 대를 정해 **카메라가 계속 따라가는 탑뷰 애니메이션**을 만드는 것이 목표
- 화면에 도로(차선·램프)와 주변 차량을 함께 그려서, 궤적 데이터가 실제로 어떤 상황인지 눈으로 확인할 수 있게 함

## 2. 데이터 조사 결과

### 2.1 로컬 현황

- 작업 머신에 NGSIM·highD 둘 다 **없음**을 확인함 (`/data`에는 argoverse2, carla뿐)
- 파이썬 환경은 conda `av2` 사용. numpy / pandas / matplotlib / opencv / scipy 모두 있음
- **ffmpeg가 없음** — matplotlib이 쓸 수 있는 writer는 `pillow`, `html`뿐임을 확인함

### 2.2 NGSIM — 즉시 사용 가능

- US DOT ITS DataHub(Socrata) API가 열려 있어 인증 없이 받을 수 있음을 확인함
- 단위는 **피트**, 샘플링 10Hz, `local_y`=종방향 / `local_x`=횡방향

| 구간 | 행 수 | 구간 길이 | 차로 구성 |
| --- | --- | --- | --- |
| us-101 | 4,802,933 | 681 m | 본선 5 + aux 1 + ramp 2 |
| i-80 | 4,566,387 | 546 m | 본선 6 + ramp 1 |
| lankershim | 1,607,319 | — | 교차로 있는 간선도로 |
| peachtree | 873,887 | — | 교차로 있는 간선도로 |

### 2.3 highD — 자동 취득 불가

- levelXdata(RWTH Aachen) **라이선스 신청**이 필요해 자동 다운로드가 불가능함
- 25Hz, 미터 단위, `recordingMeta`에 차선 표시선 좌표가 들어 있어 도로 그리기는 오히려 더 정확함
- 어댑터는 미리 작성해 두고, 파일이 확보되면 경로만 넣어 쓰는 구조로 감

## 3. 설계

### 3.1 공통 스키마 + 어댑터 구조

두 데이터셋의 단위·좌표 정의·주기·주행방향이 전부 달라서, **렌더러는 하나의 포맷만 보도록** 어댑터 층을 둠.

```
NGSIM  ─┐
        ├─→ [공통 tracks + Road] ─→ 렌더러 ─→ mp4
highD  ─┘
```

공통 좌표계로 아래와 같이 정의함.

- `x` : 주행방향 [m], **항상 + 방향으로 진행**
- `y` : 횡방향 [m], **차량 왼쪽이 +** (1차로가 화면 위쪽에 오게 됨)
- `x, y`는 차량 **중심** 기준
- tracks 컬럼: `track_id frame t x y vx vy speed yaw length width lane_id cls`

### 3.2 다운로드 전략

전체를 받지 않고 **focal이 살아있는 시간창만** 받는 3단계 방식으로 감.

1. 차선 기하 — lane별 `local_x` 평균 / `local_y` 범위 (요청 1회)
2. 차량 인덱스 — vehicle_id별 프레임 수·시간범위 (요청 1회)
3. 시간창 원본 — focal 구간의 모든 차량 행 (요청 몇 회)

결과적으로 450만 행 중 **23~50만 행만** 받으면 충분함. 받은 건 `data/`에 캐시해 재실행 시 재다운로드하지 않음.

### 3.3 카메라 / 화면

- 도로에 정렬(도로가 항상 수평)하고 focal을 화면 중앙에 고정 → 도로가 좌우로 흐르는 형태
- 기본 시야: 뒤 65 m / 앞 75 m, 도로 전폭
- 하단 HUD: 시간, focal 속도, 차로 번호, 종방향 위치, 주변차 수, 선행차 범퍼 간격

### 4.1 도로 기하를 데이터에서 유도함

외부 도로 파일 없이 **NGSIM 데이터 자체에서** 차로 배치를 뽑아냄.

- lane별 `local_x` 평균 → 차로 중심, 인접 중심의 중점 → 차선 경계
- lane별 `local_y` 범위 → 램프가 존재하는 종방향 구간

us-101 실측 결과, 차로 중심이 2.13 / 5.69 / 9.12 / 12.50 / 16.14 m로 **약 3.5 m 간격**으로 깔끔하게 나옴. 램프 구간도 실제 도로 구조와 일치함.

| 구간 | 요소 | 종방향 범위 |
| --- | --- | --- |
| us-101 | ON-RAMP | 112 ~ 200 m |
| us-101 | AUX (보조차로) | 188 ~ 412 m |
| us-101 | OFF-RAMP | 399 ~ 489 m |
| i-80 | ON-RAMP | 38 ~ 213 m |

> 램프·보조차로 3개는 lane별 평균 횡위치를 그대로 쓰면 60 cm 남짓의 단차가 생겨 그림이 깨짐. 물리적으로는 '본선 오른쪽의 같은 차로 대역'이 종방향 구간만 달리하는 것이므로, 관측량으로 가중평균한 **하나의 연속 대역**으로 합쳐 해결함.

### 4.2 출력 파이프라인

처음엔 이 환경에 ffmpeg가 없어 OpenCV로 우회했으나, 이후 설치해서 **H.264로 전환함.** 두 경로를 모두 남겨둠.

- matplotlib(Agg)으로 프레임을 그림 → RGBA 버퍼를 꺼냄 → 인코더로 넘김
- **ffmpeg가 있으면** 원시 프레임을 파이프로 밀어넣어 `libx264`(기본 crf 20)로 인코딩함. RGBA를 그대로 받아주므로 색 변환이 필요 없음
- **없으면** OpenCV `VideoWriter`(mp4v)로 떨어짐. `avc1`은 OpenCV 배포판에 라이선스 문제로 인코더가 빠져 있어 열리지 않음을 확인함
- PATH에 ffmpeg가 없어도 실행 중인 파이썬 옆(`envs/av2/bin`)을 한 번 더 찾음

| us-101 122초 영상 | 크기 |
| --- | --- |
| OpenCV mp4v | 11 MB |
| mp4v → H.264 재인코딩 | 3.7 MB |
| **H.264 직접 렌더** | **2.8 MB** |

성능은 안 그려도 되는 걸 안 그리는 방식으로 줄임.

- 도로는 최초 1회만 그리고 매 프레임 `xlim`만 옮김. 카메라가 도로에 정렬돼 있어 화면 이동이 곧 x 범위 이동임
- 차량은 사각형 패치 400개를 미리 만들어 재사용함 → 반복문 안에서 artist 생성·파괴가 사라짐

실측 **2.65배** 차이 (프레임당 31 ms vs 82 ms, 1,220프레임 환산 38초 vs 101초).

ffmpeg는 `conda install -c conda-forge ffmpeg`로 `av2` 환경에 설치함(9.0.1). dry run으로 영향 범위를 먼저 확인했고, 새 패키지만 추가되고 기존 것 중에는 `openssl` 패치 버전만 바뀌어 numpy·opencv·torch·matplotlib에는 영향 없음을 확인함.

## 5. NGSIM 데이터의 함정 4가지

작업 중 발견해서 코드에 반영한 것들.

1. **`vehicle_id`가 전역 유일하지 않음**
   us-101/i-80은 15분 녹화 3개를 합친 것이라 ID가 재사용됨. → 차량 인덱스를 `vehicle_id` + `total_frames`로
   묶어 녹화별 트랙으로 갈라낸 뒤, "시간폭과 프레임 수가 일치하는" 연속 트랙만 focal 후보로 씀.
   (`vehicle_id`만으로 묶으면 재사용된 ID가 통째로 탈락하면서 그 안의 최장 트랙까지 버려짐 —
   후보가 us-101은 663개 → **5,075개**, i-80은 1,085개 → **5,670개**로 늘었음)
   시간창을 받은 뒤 시간 gap으로 한 번 더 쪼갬.
2. **좌표가 차량 중심이 아니라 앞면 중앙임**
   → 길이 절반만큼 뒤로 밀어 중심으로 변환함. (highD는 bbox 좌상단이라 별도 보정)
3. **횡방향은 노이즈가 신호만큼 큼**
   절대적인 지터는 작음(종방향 1.2 cm / 횡방향 0.5 cm). 문제는 비율임 — 횡방향은 프레임당 실제
   이동량이 0.9 cm뿐이라 **노이즈가 신호의 0.6배**가 됨. 헤딩은 `atan2(횡속도, 종속도)`라 여기서 튐.
   → 횡방향만 종방향의 두 배 창(23프레임 ≈ 2.3초)으로 스무딩하고, 헤딩을 ±12°로 제한함.
   차선을 안 바꾼 차 기준 "5° 넘게 기울어 보이는 비율"이 2.21% → **0.77%**로 줄었음.
4. **차량 박스가 가끔 겹침**
   원본에서 같은 차로 범퍼 간격을 세어보니 us-101 **0.24%**, i-80 **2.59%**가 음수(최소 -7.2 m). 변환 문제가 아니라 NGSIM 자체의 영상 판독 오차임을 확인함. → 보정하지 않고 그대로 그림. HUD의 `gap`도 실제 값을 표시함.

## 6. 결과물

| 영상 | focal | 길이 | 해상도 | 용량 |
| --- | --- | --- | --- | --- |
| `ngsim_us-101_v1293.mp4` | 차량 1293 | 122.0 s (1,220 프레임) | 1500×376 | 2.8 MB |
| `ngsim_i-80_v2515.mp4` | 차량 2515 | 221.6 s (2,216 프레임) | 1500×440 | 6.4 MB |

둘 다 10 fps(NGSIM 실시간), H.264 crf 20으로 인코딩함. 초기 mp4v 버전 대비 각각 11 MB → 2.8 MB,
25 MB → 6.4 MB로 줄었고 화면 내용은 동일함.

### us-101 — 아침 러시아워, 681 m 전 구간 통과

focal 1293은 **4차로에 122초 내내 머무름**(차선변경 없음). 635 m를 이동해 구간을 사실상 전부 지나감.
평균 18.8 km/h, 최고 44.2 km/h, 9.1%가 3 km/h 미만. 주변 차량은 평균 184대.

화면 오른쪽 아래 램프 대역의 라벨이 순서대로 바뀜.

| 요소 | 도로 위치 | 화면에 보이는 시각 |
| --- | --- | --- |
| ON-RAMP | 112 ~ 200 m | 3 ~ 66 초 |
| AUX (보조차로) | 188 ~ 412 m | 31 ~ 104 초 |
| OFF-RAMP | 399 ~ 489 m | 72 ~ 113 초 |

즉 **온램프 합류 → 보조차로 → 오프램프 분기**가 차례로 지나감.

### i-80 — 퇴근 러시아워, 심한 정체

focal 2515도 **4차로 고정**. 222초 동안 495 m만 이동함. 평균 8.1 km/h, 최고 22.8 km/h,
**23.1%가 3 km/h 미만**이라 화면이 멈춰 보이는 구간이 많음. 주변 차량 평균 223대.
온램프(38 ~ 213 m)는 0 ~ 154초에 보임.

us-101과 눈에 띄게 다른 점은 램프가 본선에 붙어있지 않고 **고어 구간으로 분리되어 있다는 것**.
데이터에서 나온 차로 위치를 그대로 그린 결과이며 실제 도로 구조와 일치함.

> 두 focal 모두 차선변경을 하지 않음. "가장 오래 머무는 차"를 고르면 한 차로에서 꾸준히 가는 차가
> 뽑히기 때문임 — 차선변경하는 차는 대개 더 빨리 빠져나감. 차선변경 장면이 필요하면 `--track-id`로
> 지정하면 됨(예: us-101의 2113번은 2차로 → 5차로).

## 7. 검증 현황

**검증한 것**

- us-101 / i-80 **두 구간 모두 실제로 렌더링해서** 도로·차량·램프가 맞게 그려지는지 확인함
- 단위 변환 — 승용차 평균 15 ft(4.6 m), 트럭 31~53 ft, 오토바이 7.2 ft로 정상임을 확인함
- 범퍼 간격 음수 비율을 원본 데이터로 직접 세어, 코드 문제가 아님을 확인함
- highD 어댑터는 공개 포맷과 같은 구조의 **합성 파일**로 상·하행 좌표 뒤집기, bbox→중심 보정, 차선 표시선 파싱까지 통과시킴

**검증하지 못한 것**

- highD 어댑터를 **실제 highD 파일로는 검증하지 못함** (라이선스 미확보)
- 간선도로 2개 구간(lankershim, peachtree)은 교차로 때문에 구간마다 차로 구성이 달라져, 현재 로직으로는 배경이 깨짐. 궤적 자체는 읽힘

## 8. 사용법

```bash
conda activate av2
cd ~/Argoverse2study/animation

python scripts/animate_focal.py                              # us-101, 가장 오래 머무는 차
python scripts/animate_focal.py --location i-80
python scripts/ngsim_fetch.py --location us-101 --list 20    # focal 후보 보기
python scripts/animate_focal.py --track-id 2113              # 차선변경 하는 차 지정
python scripts/animate_focal.py --start-seconds 40 --max-seconds 15 --speed 2
```

주요 옵션: `--ahead` / `--behind`(시야 m), `--speed`(배속), `--smooth`(스무딩 창, 1=끔), `--gif`

> `.gitignore`가 `data/`, `output/`, `*.csv`를 제외하므로 git에는 스크립트 3개와 README만 올라감.
