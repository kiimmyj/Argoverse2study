# NGSIM / highD 파이프라인에서 얻을 수 있는 값 정리

작업일: 2026-08-19 · 관련 문서: focal 추종 탑뷰 애니메이션 구축

---

## 0. 값의 층위

애니메이션을 만들면서 데이터가 4단계를 거침. 각 단계마다 꺼내 쓸 수 있는 값이 다름.

```
① 원본 필드      NGSIM API가 주는 25개 컬럼 (피트 단위)
      ↓ 어댑터
② 공통 포맷      13개 컬럼 (미터, 차량 중심, 주행방향 +x)
      ↓ 렌더 시점
③ 장면 계산값    선행차 간격, 주변차 수, 도로 기하
      ↓ 집계
④ 통계량         속도 분포, 밀도, 차선변경 비율 등
```

---

## 1. ① NGSIM 원본 필드 (25개)

`data.transportation.gov` API가 주는 전체 컬럼임. **단위는 전부 피트 계열**.

| 필드 | 단위 | 의미 | 현재 받는가 |
| --- | --- | --- | --- |
| `vehicle_id` | — | 차량 ID (**15분 녹화 내에서만 유일**) | ✅ |
| `frame_id` | — | 프레임 번호 (1/10초) | ✅ |
| `total_frames` | — | **그 녹화 안에서** 그 차량의 총 프레임 수 | 인덱스에서 사용 |
| `global_time` | ms | epoch 시각 | ✅ |
| `local_x` | ft | 횡방향 위치, 구간 **좌측 끝** 기준 | ✅ |
| `local_y` | ft | 종방향 위치, 구간 **진입 끝** 기준 | ✅ |
| `global_x` / `global_y` | ft | 주 좌표계(state plane) 절대좌표 | ❌ |
| `v_length` / `v_width` | ft | 차량 길이 / 폭 | ✅ |
| `v_class` | — | 1=오토바이, 2=승용, 3=트럭 | ✅ |
| `v_vel` | ft/s | 순간 속도 | ✅ |
| `v_acc` | ft/s² | 순간 가속도 | ❌ |
| `lane_id` | — | 차로 번호 (1=좌측) | ✅ |
| `preceding` | — | 같은 차로 **앞차 ID** (0=없음) | ❌ |
| `following` | — | 같은 차로 **뒤차 ID** | ❌ |
| `space_headway` | ft | 앞차와의 거리 (앞면중앙 기준) | ❌ |
| `time_headway` | s | 차두시간 (**9999.99 = 앞차 없음**) | ❌ |
| `o_zone` / `d_zone` | — | 출발 / 도착 존 | 간선도로만 |
| `int_id` | — | 교차로 ID (0=구간 내부) | 간선도로만 |
| `section_id` | — | 구간 ID | 간선도로만 |
| `direction` | — | 1=동, 2=북, 3=서, 4=남 | 간선도로만 |
| `movement` | — | 1=직진, 2=좌회전, 3=우회전 | 간선도로만 |
| `location` | — | 구간명 | 필터로 사용 |

### 구간별 제공 차이 (실제 확인함)

| 구간 | 간선도로 전용 필드 |
| --- | --- |
| us-101 | 컬럼은 있으나 값이 전부 문자열 `"NA"` |
| i-80 | **컬럼 자체가 없음** |
| lankershim / peachtree | 전부 실제 값이 채워짐 |

> 파싱할 때 주의할 점임. us-101을 숫자로 읽으면 `"NA"` 때문에 컬럼 전체가 문자열이 됨.

> `total_frames`는 이후 focal 선택에 쓰기로 함. ID가 재사용돼도 녹화마다 값이 달라
> `vehicle_id`와 함께 묶으면 진짜 트랙 단위로 갈라짐.

### 현재 안 받고 있지만 쓸모 있는 필드

애니메이션에 당장 필요 없어서 뺐지만, 한 줄만 고치면 같이 받을 수 있음 (`ngsim_fetch.py`의 `COLS`).

- `preceding` / `following` — **앞뒤차 관계를 데이터가 직접 알려줌**. 지금은 직접 계산 중임
- `space_headway` / `time_headway` — 차간거리·차두시간을 원본이 제공함
- `v_acc` — 가속도. 단 NGSIM 가속도는 노이즈가 심한 걸로 알려져 있음

## 2. ② 공통 포맷으로 변환된 값 (13개)

`traffic_data.py`가 NGSIM·highD를 동일한 형태로 맞춰줌. **여기부터는 미터·초 단위임**.

| 컬럼 | 단위 | 설명 | 생성 방식 |
| --- | --- | --- | --- |
| `track_id` | — | `{vehicle_id}_{조각번호}` | 시간 gap으로 분할 |
| `frame` | — | 0부터 시작하는 프레임 번호 | 시각 정규화 |
| `t` | s | 시간창 시작 기준 경과시간 | 시각 정규화 |
| `x` | m | 주행방향 위치 | `local_y × 0.3048`, **앞면중앙 → 중심 보정** |
| `y` | m | 횡방향 위치 (차량 왼쪽이 +) | `-local_x × 0.3048`, 중심 보정 |
| `vx` / `vy` | m/s | 축별 속도 | 스무딩한 위치의 수치미분 |
| `speed` | m/s | 속력 | `hypot(vx, vy)` |
| `yaw` | rad | 진행방향 각도 (0 = +x) | `atan2(vy, vx)`, ±12°로 제한 |
| `length` / `width` | m | 차량 크기 | `× 0.3048` |
| `lane_id` | — | 차로 번호 | 원본 그대로 |
| `cls` | — | `car` / `truck` / `moto` | `v_class` 매핑 |

### 변환 과정에서 생기는 값 (원본에 없음)

- **`track_id`** — 원본의 `vehicle_id`는 재사용되므로 시간 gap으로 쪼개서 만든 진짜 트랙 ID임
- **`yaw`** — NGSIM은 헤딩을 주지 않음. 궤적 미분으로 만들어냄
- **차량 중심 좌표** — 원본은 앞면 중앙 기준이라 길이 절반만큼 보정한 값임

## 3. ③ 렌더 시점에 계산되는 값

| 값 | 설명 |
| --- | --- |
| 선행차 간격 (`gap`) | 같은 차로 앞차와의 **범퍼 간 거리** [m]. 음수 가능 (2장 참고) |
| 주변차 수 | 화면 범위(뒤 65 m ~ 앞 75 m) 안의 차량 대수 |
| focal 종방향 위치 | 구간 진입점 기준 현재 위치 [m] |

### 도로 기하 (데이터에서 유도함)

외부 지도 없이 NGSIM 데이터만으로 뽑아낸 값들임.

| 값 | 유도 방법 | us-101 실측 |
| --- | --- | --- |
| 차로 중심 | lane별 `local_x` 평균 | 2.13 / 5.69 / 9.12 / 12.50 / 16.14 m |
| 차로 폭 | 인접 중심 간격의 중앙값 | 약 3.5 m |
| 차선 경계 | 인접 중심의 중점 | — |
| 램프 구간 | lane별 `local_y` 최소·최대 | ON 112~200 / AUX 188~412 / OFF 399~489 m |
| 구간 전체 길이 | 전 차로 `local_y` 범위 | 681 m (i-80은 546 m) |

## 5. 데이터 품질 관련 수치

애니메이션을 만들면서 실제로 세어본 값들임.

| 항목 | us-101 | i-80 | 판단 |
| --- | --- | --- | --- |
| 같은 차로 범퍼 간격이 음수 | 0.24 % | 2.59 % | 원본 판독 오차. 최소 -7.2 m |
| 범퍼 간격 중앙값 | 10.6 m | 6.7 m | 정상 범위 |
| 속도 > 100 km/h | 0 샘플 | 8 샘플 (0.0016 %) | 원본 `v_vel`에도 이미 존재하는 이상치 |
| 헤딩 제한(±12°)에 걸림 | 드묾 (p95 = 2.74°) | 드묾 (p95 = 5.44°) | 정체 구간 노이즈 억제용 |

### 교차 검증

파생 속도의 평균이 원본 `v_vel` 평균과 **소수점까지 일치함**(us-101 23.3 km/h, i-80 12.7 km/h). 피트→미터 변환과 수치미분이 맞게 돌아간다는 뜻임.

## 6. 아직 안 쓰지만 바로 뽑을 수 있는 값

지금 파이프라인에 이미 있는 정보만으로 계산 가능한 것들임. 예측 모델 입력 후보로 정리함.

**차량 단위**

- 가속도 — `speed` 미분, 또는 원본 `v_acc` 필드
- 차두시간(THW) — `gap / speed`
- 충돌예상시간(TTC) — `gap / 상대속도`
- 차선변경 이벤트 — `lane_id` 변화 시각과 소요시간 (트랙의 약 20%에서 발생)
- 차로 내 횡방향 오프셋 — `y` 와 차로 중심의 차이

**주변 상황**

- 주변 8대 (좌/우 × 앞/옆/뒤) — highD는 필드로 주지만 NGSIM은 계산해야 함
- 앞뒤차 상대속도 / 상대위치
- 국소 밀도 — 반경 N m 안의 차량 수

**교통류 단위**

- 밀도 · 유량 · 공간평균속도 (Edie 정의)
- 차두시간 분포, 속도 분포
- 시공간도(time-space diagram) — 정체파 전파를 볼 수 있음

**예측 모델 입력**

- 과거 궤적 + 주변차 상대좌표 → Argoverse 2에서 쓰던 구조와 동일하게 만들 수 있음
- Argoverse는 10Hz / 5초 관측 + 6초 예측인데, NGSIM도 10Hz라 **리샘플링 없이 그대로 맞음**

## 7. highD에서 추가로 얻는 값 (문서 기준, 미검증)

라이선스 미확보라 실제 파일로 확인하지 못함. 공개 포맷 명세 기준임.

**`tracks.csv`** — NGSIM에 없는 것들

- `xAcceleration` / `yAcceleration` — 축별 가속도
- `dhw` / `thw` / `ttc` — 차간거리 · 차두시간 · 충돌예상시간을 **직접 제공**
- `frontSightDistance` / `backSightDistance` — 관측 가능 거리
- `precedingId`, `followingId`, `leftPrecedingId`, `leftAlongsideId`, `leftFollowingId`, `rightPrecedingId`, `rightAlongsideId`, `rightFollowingId` — **주변 8대 ID를 전부 제공**

**`tracksMeta.csv`**

- `numLaneChanges` — 차선변경 횟수
- `minTTC` / `minTHW` / `minDHW` — 위험도 지표 최솟값
- `traveledDistance`, `meanXVelocity`, `drivingDirection`

**`recordingMeta.csv`**

- `upperLaneMarkings` / `lowerLaneMarkings` — **차선 표시선 좌표를 직접 제공** (NGSIM은 유도해야 함)
- `speedLimit`, `locationId`, `duration`, `numVehicles` / `numCars` / `numTrucks`

> 정리하면 highD는 **파생값을 데이터가 이미 계산해 줌**. NGSIM은 위치·속도만 주므로 나머지는 직접 만들어야 함. 대신 NGSIM은 지금 바로 받을 수 있음.
