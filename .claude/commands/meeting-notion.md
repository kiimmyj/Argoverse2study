# 미팅용 노션 문서 만들기 — $ARGUMENTS

읽는 사람은 **교수님**이다. 미팅은 짧고, 원하는 건 "그래서 결론이 뭐냐"와 "뭘 정해 줘야 하냐"다.
**스크롤이 생기면 ③이 안 읽히는데, 미팅에서 실제로 필요한 건 ③이다.**

---

## 골격 — 이 셋을 순서대로. 늘리지 말 것

### ① 결론 (인용 블록 안에 한 문장)

바로 아래 **신뢰도**를 `확정 / 판정 불가 / 추정` 중 하나로 적고, **언제 확정되는지**를 쓴다.

> ⚠️ **결과가 애매하면 "아직 판정할 수 없다"를 먼저 쓴다.** 숫자를 먼저 쓰면 "실패했다"로
> 굳어 읽힌다. 판정 불가면 **왜 못 하는지**를 짧은 목록으로(표보다 목록이 짧다).

### ② 숫자

- **그림 한 장**을 맨 위에(아래 「그림」 참조). 캡션은 **축 설명이 아니라 읽는 법**을 쓴다.
- 그림 바로 밑에 **"이 그림이 핵심입니다"** 한 문장 — 그림에서 뭘 봐야 하는지.
- **주 지표만 한 줄짜리 표** 하나. 나머지는 `A (+3.8%) · B (+5.3%)` 로 한 줄에 몰아라.
- 불릿 2~4개로 "일정한가 / 어디서 갈렸나 / 비용".
- ⚠️ 블록 하나로 **반대 해석의 여지**를 적는다. 유리한 쪽만 쓰지 않는다.

### ③ 결정이 필요한 것

번호 매긴 질문 **2~3개**. 각 항목에 **대가**를 적는다(예: "추가 1런 = 46시간").

> 첫째 질문은 **진행 중인 실험의 결과별 분기를 미리 정하는 것**으로 한다. 값을 보고 정하면
> 사후 해석이 된다. 표로: `| 결과가 이러면 | 제안 |`

## 분량 — 한 화면 ≈ **2,000자**

```bash
python -c "import pathlib;print(len(pathlib.Path('docs/<파일>.md').read_text()))"
```

⚠️ **`wc -c` 를 쓰지 마라 — 바이트다.** 한글은 3바이트/자라 3배로 나오고, 멀쩡한 문서를
"목표의 두 배"로 착각해 잘라내게 된다(2026-11-05 에 그랬다).

## 그림

**미팅용은 따로 그린다.** 분석용 그림은 주석이 많고 가로가 길어 빔에 안 맞는다.

- **두 패널까지.** 패널마다 제목이 **주장**이어야 한다 — "① R1 은 처음부터 끝까지 R0 위에 있다"
  처럼. "val minADE6 추이" 같은 제목은 아무것도 말하지 않는다.
- **분석 스크립트 안에 함수로 넣어라**(`fig_meeting()` 식). 손으로 그려 붙이면 다음 런에서 썩는다.
- **진행 중인 런은 범례에 `(진행 중 19/49)` 로 적고, 그림 안에 "판정 아님"을 박는다.**
- 런끼리 **축과 색을 통일**한다(시각화 요건 #6). **검증 에폭마다 점**을 찍는다(#7).

**그리고 나서 반드시 (시각화 요건 #9):**

1. **Read 로 그림을 직접 열어 본다.** 실제로 매번 겹침이 나왔다 —
   끝점 라벨은 **진행 중인 런에서 선이 가운데서 끝나** 다른 선 위에 얹힌다. **범례를 써라.**
   글상자는 데이터 꼭지점을 덮는다. y축에 자리를 만든 뒤 배경 박스를 깔아라.
2. **그림 속 숫자를 다른 코드 경로로 교차검증한다.** 로그를 따로 긁어 다시 세서 맞는지 본다.

⚠️ **창을 맞춰라.** 두 런의 폭을 비교할 때 한쪽은 37에폭, 한쪽은 10에폭으로 재면 비교가
성립하지 않는다. **공통 에폭 창**에서 재고, 캡션에 `에폭 1~19 공통 10개에서:` 처럼 밝혀라.
(이 함정은 문서 본문에서 세 번, 그림 주석에서 한 번 재발했다.)

## 숫자

**손으로 쓰지 않는다.** 생성기가 만든 `viz/*/numbers.json` 에서 꺼내고, 문서에 박은 값을
**전수 대조**한다. 상세·측정 방법·오독 기록은 전부 생성 문서로 **링크**한다.

```bash
# 문서에 쓴 값이 전부 출처와 맞는지
python - <<'PY'
import json, pathlib
d = json.loads(pathlib.Path("viz/<...>/numbers.json").read_text())
doc = pathlib.Path("docs/<파일>.md").read_text()
for s in ["0.795", "0.830", "+0.035", ...]:
    print(("✅" if s in doc else "❌"), s)
PY
```

## 올리는 순서 — 어기면 되돌리기 번거롭다

1. **먼저 커밋한다.** 커밋 전에 노션에 밀면 머리말에 `작성 ?` 가 박히고,
   그 뒤 커밋해도 **본문 해시가 같아 다시 안 올라간다**.
   (`push_v4_docs.py` 가 이제 막지만 순서를 지키는 게 맞다.)
2. `~/paper-kb/tools/push_v4_docs.py` 의 `미팅` GROUPS **맨 앞**에 파일명을 넣는다.
3. `python -I ~/paper-kb/tools/push_v4_docs.py` (MCP 커넥터 말고 **이 경로**로. 커넥터는 다른 계정이다)
4. **올라간 걸 읽어서 확인한다.** 스크립트의 "끝" 은 올라갔다는 증거가 아니다.
   핵심 문구·숫자가 있는지, **이미지 블록이 실제로 생겼는지**, 낡은 문장이 사라졌는지 본다.

## 끝내기 전 체크리스트

- [ ] 2,000자 안쪽인가 (**글자 수**로 쟀나)
- [ ] 첫 줄이 결론인가. 신뢰도와 "언제 확정되는가"가 붙어 있나
- [ ] 그림을 **직접 열어 봤나**. 겹친 글씨가 없나
- [ ] 그림 속 숫자를 **다른 코드로** 다시 셌나. 창을 맞췄나
- [ ] 문서의 모든 수치를 출처와 전수 대조했나
- [ ] ③이 **2~3개**이고 각각 **대가**가 적혀 있나. 첫째가 **사전 등록**인가
- [ ] 커밋 → 푸시 → **읽어서 확인** 순서를 지켰나
- [ ] 불리한 해석도 ⚠️ 로 적혀 있나
