## 0. 요약

- AV2 원본을 **① 궤적 표현 변환 → ② HD map 규칙화 → ③ 품질 점검·정제 → ④ 평활·다운샘플링** 순으로 다뤘음. 품질 수치는 표본이 아니라 **train 199,908 + val 24,988 전수**로 확보함
- 성과로 쓸 수 있는 것
  - (a, h) 표현이 정보 손실 없이 궤적을 복원함 (과거 5초 ADE 0.007 m)
  - HD map의 좌측 이웃 차로 **45.2%가 대향차로**임을 찾아 규칙으로 걸러냄
  - 정제 대상이 **0.17%뿐**임을 전수로 보이고, 결함 2건을 고쳐 재학습하니 3 seeds 모두 개선됨
- ⚠️ **ADE가 가장 낮은 버전(SIMPL 재현, 모델 담당)은 저자 전처리를 그대로 썼음** — ①~④가 그 모델에는 들어가 있지 않음. 보고서에서 어떻게 엮을지 §4-1에서 정해야 함

## 2. 보고서 본문 재료

### 2.1 데이터와 표본 구성

- AV2 Motion Forecasting — train 199,908 / val 24,988 / test 24,984 시나리오. 시나리오당 11초 @ 10 Hz = 관측 5초(50 step) + 예측 6초(60 step)
- 시나리오 파일에는 위치·heading·속도·객체 종류만 있고 **가속도가 없음** → a는 유도해야 함
- HD map(`log_map_archive_*.json`)은 차로마다 중심선, 좌·우 경계, 차선 표시 종류, 차로 종류(차량/버스/자전거), 교차로 여부, 선·후행 연결, 좌·우 이웃 차로를 줌. v3 초기에는 이 중 **중심선 좌표만** 썼음
- **1 시나리오 = 학습 표본 1개** (9/3 결정 — 창을 굴려 표본을 늘리지 않음)

### 2.2 궤적 표현 변환 — (x, y) → (a, h)

- 좌표는 focal 차량의 마지막 관측 시점 위치·방향 기준으로 정규화함
- a = 속도 증분(첫 값이 초기 속력 v₀), h = 위치 차분으로 구한 진행 방향
  - v₀가 있으면 과거 5초를 **ADE 0.007 m**로 복원함. v₀ 없이는 ADE 6.81 m (val 300)
  - → v₀를 a의 첫 값으로 싣는 이유
- h를 AV2 heading으로 쓰지 않은 이유: AV2 heading은 **차체 방향**이라 진행 방향과 슬립각(p95 9.86°)만큼 어긋남
  - 방향만 바꿔 궤적을 다시 굴리면 최종 오차가 AV2 heading 1.693 m → 진행 방향 **0.145 m**(1 m/s 미만만 AV2로 보조, 12배 정확, val 3,000)
- 9/3의 φ = κ + θ는 **h = k + θ**(k 차로 방향각, θ 잔차각)로 구현함 — 곡률 대신 각도로 분해해서 잔차 편향이 거리에 따라 누적되지 않음
- 입력 표현 비교 (val 2,000, 15 epoch, minADE6)

| 입력 | 채널 | minADE6 | 기준 대비 |
| --- | --- | --- | --- |
| 기존 (x, y, vx, vy, heading) | 5 | 1.318 | — |
| (v, a, sin h, cos h) | 4 | **1.265** | **−4.0%** |
| (a, h) | 2 | 1.406 | +6.7% |

> 💡 2채널은 정보를 다 보존하는데도(복원 0.007 m) 나빴음 — "정보를 보존하는 표현"과 "신경망이 쓰기 쉬운 표현"이 다르다는 결과

### 2.3 HD map 전처리

- v3: focal 주변 차로 **20개 × 중심선 10점**을 입력으로 넣음
- 규칙 feature **10채널** 추가 — 진행방향 단위벡터 2, 같은 방향 여부, 교차로 여부, 차로 종류 3, 좌·우 차선변경 가능, 규칙상 도달 가능
- **핵심 발견 — 지도의 좌측 이웃 차로 45.2%가 대향차로임**(우측 0.1%)
  - "이웃 = 변경 가능"으로 두면 좌측 차선변경의 절반이 역주행이 됨
  - → 방향이 같고, 넘을 수 있는 차선 표시(점선·표시 없음)일 때만 변경을 허용함
- 이동 규칙 4종: 진행(successor만, predecessor 금지) / 좌변경 / 우변경 / U턴(교차로 최대 3단계 경유)
- 검증 — 실제로 지나간 미래 차로가 규칙상 도달 가능한가 (처음 보는 400개)

| | 적중 | 후보 차로 | 섞인 역주행 차로 |
| --- | --- | --- | --- |
| 규칙 없음 | — | 30.5개 | 11.85개 |
| **규칙 적용** | **97.7%** | **15.0개** | **1.63개** |

- 처음에는 78.2%였는데, 원인은 규칙이 아니라 **차로 매칭**이었음. 교차로에서는 차로가 겹치므로 시작 차로를 하나가 아니라 **후보 4개**로 잡자 98.3%(튜닝 표본)
- 지도 위 시각화: 차선 표시(실선·점선·이중선·횡단보도)를 지도 데이터에서 그대로 읽어 그림 (`docs/v3_map_visualization.md`)

### 2.4 데이터 품질 점검·정제 (train + val 전수)

| 항목 | 결과 |
| --- | --- |
| AV2 heading 라벨 튐 (249,880 시나리오 / 25,737,880 step) | 스텝 간 변화 p99.99 7.3°, 30° 초과 **11 step**(전부 train, val·test 0건) → 30° 초과 시 직전 값 유지 가드 |
| 맵 이탈 — 경로 없음 / 도로 밖 (train) | 3.91% / 4.58%. 주범은 지도가 아니라 **보행자·자전거 focal(7.77%)**. 차량만 보면 0.78% / 0.014% |
| heading 오기입 — focal AV2 heading 180° 뒤집힘 | train 666건(0.33%), 그중 차량 209건(0.10%). val의 같은 차량 18건은 minADE6 **15.07 m**(전체 1.49 m) |
| 커버리지 실패 (정답이 후보 경로 밴드 밖, train) | 14.38% — 대부분 회전·차선변경이라 버리면 그 행동이 통째로 빠짐 |

- 9/17 지시("양을 보고 버릴지 보정할지 결정")의 답: **버릴 것은 거의 없고, 고칠 것이 있음**
  - 결함 2건 수정 — ① 후보 차로 거리를 중심선 정점이 아니라 선분까지로 계산(차량 '경로 없음'의 91%가 이것 때문), ② 뒤집힌 heading을 이동 구간 기준으로 교정
  - 고친 뒤 폐기 대상은 train **0.17%(약 340건)**
  - 보정한 데이터로 재학습하니 **3 seeds 모두 개선**(paired Δ minADE6 −0.043)
  - 보행자·자전거를 버리면 오히려 나빠짐(val minADE 1.490 → 1.522) → 버리지 않음
- 버릴 수 없는 것: **창 양 끝 0.5초 속도 램프**
  - 위치 차분 속력이 첫 step에서 실제의 0.469배, 끝 step에서 0.482배임
  - 데이터 생성 방식에서 오는 것이라 거의 모든 시나리오에 있음
- 빈도 (val): U턴 73건(0.29%, 회의 결정대로 제외), 차로변경 627건(2.51%)

### 2.5 평활·다운샘플링

- 9/17 기준 "직진에서 heading vs time이 일관되게 유지되는가"로 평가함 (val 3,000)
- 데이터 특성
  - 위치 잡음 = 저주파 흔들림(σ 13.5 cm) + 백색(σ 0.77 cm) + 두꺼운 꼬리
  - 신호와 잡음이 갈리는 주파수는 0.6~1.0 Hz임
- 기존 평활 SG(5,2)는 2 Hz에서 **아무 효과가 없었음**(직진 heading 떨림 p90 3.23 vs 3.23 °/s)
- 권고안: **가우시안 σ = 0.25 s(차단 0.53 Hz) + 경계 2차 외삽**

| 지표 | 기존 | 변경 후 |
| --- | --- | --- |
| 직진 heading 떨림 p90 | 2.70 °/s | **2.22 °/s** (−18%) |
| jerk p90 | 9.75 m/s³ | **7.61 m/s³** (−22%) |
| 회전량 보존 | 1.022 | 1.022 (감쇠 없음) |

- 모델 정확도로는 효과가 안 보였음
  - 평활 −0.053: seed별 부호가 갈려 **검출 불가** → 채택 보류
  - 2 Hz 다운샘플링 +0.072: **3 seeds 모두 나쁨** → 10 Hz 유지
- 병렬 처리(9/10): 전처리 결과를 캐시로 구워 읽기가 원본보다 약 1,500배 빨라졌고, train+val 전체를 워크스테이션 다중 코어로 병렬 처리함

### 2.6 최저 ADE 버전(SIMPL)의 전처리 — 모델 담당 결과와 짝

- 저자 전처리 코드를 수정 없이 사용함. 시나리오당 파일 1개, 총 30 GB, 처리 시간 val 4분 · train 40분
- agent는 110 step(관측 50 + 예측 60)
- 차로는 15 m 세그먼트 × 노드 10개로 쪼갬
- 입력 채널
  - 차로 16채널: 위치·방향·교차로·종류·좌우 차선 표시·좌우 이웃
  - agent 14채널
- **§2.2~2.5의 평활·정제는 넣지 않았음**(한 번에 하나만 바꾸는 원칙)
- (a, h) 입력판(R1)은 재전처리 없이 로더에서 변환함
- 주의: SIMPL은 관측 50 step 중 **앞 2 step을 버림** → (a, h)는 자른 뒤에 만들어야 v₀가 살아남음

## 5. 작년(3차년도) 보고서와 이어 쓰기

작년 보고서에서 노란 형광펜(음영)이 칠해진 곳은 2장의 「인지 증강화 기반 협력 자율주행 시나리오 개발 및 성능 평가, 객체 이동궤적 예측 모델 개발 (고려대학교 세종산학협력단)」 한 절뿐임. 그 안은 두 덩어리임.

- ① **동적 객체 이동 궤적 예측 모델 개발** — 개요 → 데이터 개요 → 데이터 탐색(컬럼 표) → 시각화·EDA → 그래프 기반 학습 데이터 구성(전처리) → 모델링 프레임워크
  - **김영진 담당은 "데이터 탐색 ~ 학습 데이터 구성" 자리임**
- ② **주행 성능 평가 지표 조사** — 시나리오·지표 담당 자리로 보임
- 형식
  - 개조식, 문장 끝은 "~함 / ~임"
  - 소제목마다 표나 그림 하나
  - 그림 캡션은 "그림 Argoverse2 데이터 시각화" 식
