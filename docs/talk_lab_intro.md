## 2 · Argoverse 2

자율주행차가 6개 도시를 실제로 돌아다니며 **자기 인식 시스템으로 주변을 추적한 기록**임.

| 장면 하나 |   |
| --- | --- |
| **길이** | **11초** (0.1초 간격). **앞 5초를 주고 뒤 6초를 맞힘** |
| **추적 대상** | 중앙 **24대** (2~94대). `VEHICLE` 79% · `PEDESTRIAN` 8% · `BUS` 1% · `CYCLIST` 0.7% · 나머지 정적 객체 11% |
| **지도** | 차선 조각 중앙 **88개** — 차선이 어디로 이어지는지까지 같이 옴 |
| **규모** | 학습 **20만** · 검증 **2만 5천** 장면 |

전 세계가 **같은 시험지**로 채점함. 그래서 "이 방법이 더 낫다"를 말할 수 있음.

### 트랙이 다 같지 않음 — 절반 이상이 `TRACK_FRAGMENT`

AV2 는 트랙마다 **`TrackCategory`** 를 붙임. 넷뿐이고, 설명은 공식 정의임.

| `TrackCategory` | 비율 | 공식 정의 |
| --- | --- | --- |
| **`TRACK_FRAGMENT`** (0) | **58%** | 몇 step 만 관측된 **저품질** 트랙 — 5초를 다 못 채움 |
| `UNSCORED_TRACK` (1) | 22% | 품질은 쓸 만하나 **채점 안 함** — 맥락 입력용 |
| `SCORED_TRACK` (2) | 12% | AV 와 관련된 **고품질** 트랙 — **다중 agent** 챌린지에서 채점 |
| **`FOCAL_TRACK`** (3) | 4% | **장면을 만든 트랙** — **단일 agent** 챌린지의 채점 대상 |
| AV (ego) | 4% | 데이터를 모은 차. ⚠️ **`TrackCategory` 가 아님** — `track_id == "AV"` 로 따로 뽑음 |

## 3 · Multi-modal

![실제로는 우회전했음. 하지만 과거 5초만 봐서는 알 수 없음.](../viz/talk/t2_answer.png)

![모델이 낸 후보 여섯 개. 셋은 직진, 셋은 우회전으로 갈렸음.](../viz/talk/t3_modes.png)

과거만 봐서는 **직진인지 우회전인지 알 수 없음.** 그래서 모델은 답을 하나로 찍지 않고 **후보 여섯 개**를 냄. 채점은 **그중 정답에 제일 가까운 하나**로 함.

> Trajectory Prediction 에서 대부분 K =6 번 찍게 해 주고 제일 잘 찍은 걸 학습

> 현실에서도 차는 여러 가능성을 동시에 염두에 두고 움직이니까.

## 4 · 대부분의 모델

지도와 주변 차의 과거를 넣으면 후보 여섯 개가 나옴. 모델마다 구조는 다른데, **입력을 적는 방식은 거의 다 똑같음 — (x, y) 좌표**임.

> 매 0.1초마다 "지금 여기 있었다"를 좌표로 적어서 넣음.

## 5 · 현재 작업과의 차이

![왼쪽 — 같은 움직임, 길의 방향만 다름. 가운데 — 좌표로 적으면 숫자가 통째로 다름. 오른쪽 — (a, h)로 적으면 a는 그대로, h만 통째로 밀림.](../viz/talk/t4_repr.png)

### **"어디에 있었나" 대신 "어떻게 움직였나"로 적으면 쉬워질까?**

**a** = 얼마나 빨라졌나 · **h** = 어디를 향하나. 둘이면 궤적이 그대로 복원됨.

**같은 우회전이면 길이 어디를 향하든 오른쪽 숫자는 거의 같음.** 좌표는 통째로 달라짐. 모델 입장에서는 **"우회전은 이런 모양"을 한 번만 배우면 되는** 셈임.

## 6 · 현재상황

**전에는 모델을 직접 만들었음.** 지금은 **이미 검증된 SOTA 에 (a, h) 를 붙여** 비교함.
직접 만들면 무엇이 효과를 냈는지 분리가 안 되는데, 남의 모델 위에서는 **한 번에 하나만** 바꿀 수 있음.

### 먼저 어디에 붙일지를 골랐음

- AV2 SOTA **7개**를 채널 단위로 조사함 — 입력에 진행방향이 이미 있는지, (a, h) 를 끼울 자리가 있는지.
- 실제로 **붙일 수 있는 건 넷**뿐이었음. `ProphNet`·`GANet` 은 **코드가 공개된 적이 없고**,
  `QCNet` 은 학습에 **GPU 메모리 160 GB** 가 듦 (여기 장비는 24 GB).
- **`SIMPL` 선정** — 순수 PyTorch 라 이 장비에서 바로 돎 · MIT 라이선스 ·
  디코더에 **출력 형식 스위치가 이미 있어** (a, Δθ) 가 분기 하나로 들어감 · 입력 교체가 두 곳뿐.

### 그 위에서 한 번에 하나씩 — R0 → R3

| 단계 | 무엇을 바꾸나 | 상태 |
| --- | --- | --- |
| **검증** | 아무것도 — 저자 가중치를 우리 경로로 재평가 | ✅ **0.777** · 저자 보고치와 일치 |
| **R0** | 아무것도 — 원본을 우리 장비에서 | ✅ **0.795** |
| **R1** | **입력만** (a, h) | ✅ **0.830** |
| **R0-s43** | **난수 씨앗만** 42→43 · 사다리가 아니라 **자** | ✅ **0.801** |
| **R2** | **출력도** (a, Δθ) + Frenet 적분 | 대기 |
| **R3** | `Forecast-MAE` 에 같은 걸 · **다른 구조에서도 같은지** 보는 대조군 | 대기 |

> **R0-s43 이 사다리가 아니라 자인 이유** — 아무것도 안 바꾸고 **씨앗만** 바꿔도 숫자는 흔들림.
> 그 폭을 모르면 R1 의 차이가 **효과인지 운인지** 말할 수 없음. 자를 먼저 만드는 것임.
> 런 하나에 **46시간**씩 듦.

## AI 활용방안 — Claude Code

혼자 하는 작업인데 **동시에 여러 갈래**가 돎. 사람이 붙어 있어야 하는 구간을 없애는 게 목표임.

|   | 무엇을 | 왜 |
| --- | --- | --- |
| **세션 병렬 (fork)** | 지금도 두 세션이 각각 다른 갈래를 잡고 있음 | 46시간짜리 학습을 기다리며 놀지 않으려고 |
| **야간 논문 에이전트** | 매일 새벽 4시 cron. **논문 한 편마다 세션을 따로** 띄워 읽고 정리함 | 한 세션에서 여러 편 읽으면 맥락이 쌓여 뒤로 갈수록 엉성해짐 |
| **시각화 전용 에이전트** | 체크포인트를 받아 그림과 리포트만 만듦. **학습 금지·코드 수정 금지**를 규칙으로 박아 둠 | 분석하다가 모델을 건드리면 결과를 못 믿음 |
| **반복 절차를 명령으로** | 오늘 이 문서를 만든 절차도 `/meeting-notion` 으로 들어가 있음 | 매번 다시 설명하지 않으려고 |
| **무인 체인** | 11-04 08:36 학습 완주 → **08:39 다음 학습이 사람 없이** 떴음 | GPU 가 노는 시간을 없애려고 |

> **중요한 건 "맡기는 법"이었음.** 무인 체인은 종료 코드를 안 믿음 —

> 체크포인트 파일이 있는지, 검증이 37번 돌았는지, 오류가 0건인지를 **직접 확인**하고 다음을 띄움.

> 야간 에이전트도 몇 편을 읽을지·언제 멈출지를 **모델이 아니라 스크립트가** 정함.

> 한 번 맡겼다가 사용량을 통째로 태운 적이 있어서.
