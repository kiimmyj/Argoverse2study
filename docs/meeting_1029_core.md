> 핵심만. 근거·출처·모델별 상세는 📘 개요의 **「(a, h) 효용성 평가 — AV2 SOTA 모델 조사」** 에 있습니다.

1. v4 는 **어떤 요인이 성능을 만드는지 분리되지 않아** 잠정 보류합니다. 근거 있는 요소 넷을 다 합쳤더니 오히려 나빠졌습니다

## 1. 왜 v4 를 보류하는가

![v4 보류 근거](../viz/meeting_1029/m1_v4_why.png)

1. 개별 요인의 효과가 **0.005~0.08 m** 규모라 seed 잡음과 섞입니다. 부호가 갈리는 것도 많습니다
2. 근거가 확인된 넷(cleansing · 평활 · lane-yaw · 주변 차량)을 **전부 합쳐 100 epoch × 5 seed** 를 돌렸더니 **1.4038** — 기준(좌표 벌점만 · 30 epoch) **1.3591** 보다 +0.045 나빴습니다. 5 seed 전부 기준의 3 seed 전부보다 나쁩니다
3. 구조적 상한도 걸려 있습니다 — 후보 경로 집합의 **오라클 경로조차 정답에서 평균 1.079 m**. 목표가 minADE6 ≤ 1.0 인데 상한이 거기 있습니다
4. 덧붙여 v1~v4 는 **공부하면서 만든 것**이라 클래스명·용어·레벨의 의미가 버전마다 달라, "개선/퇴행"을 같은 자로 못 잽니다

> **보류이지 폐기가 아닙니다.** 여기서 얻은 전처리(평활 + 다운샘플링), 데이터 cleansing, 상황 군집 8개, 시각화 하네스는 그대로 가져갑니다

## 2. 조사의 결론 — invariance 가 전부를 가른다

### 먼저 용어 — invariance 가 뭔가

**입력을 어떻게 놓고 보든 결과가 변하지 않는 성질**입니다. AV2 좌표는 도시 좌표계라 **임의**라서, 같은 교차로 우회전이 로그마다 북쪽을 향하기도 하고 동쪽을 향하기도 합니다. 사람에겐 같은 상황인데 숫자로는 전혀 다릅니다.

| 같은 장면을 지도에서 90° 돌리면 | 결과 |
| --- | --- |
| 절대 위치·절대 heading `(x, y, h)` 를 넣은 경우 | **숫자가 전부 바뀜** → 모델에겐 처음 보는 장면 |
| 상대량 `(거리, 상대각)` 만 넣은 경우 | **하나도 안 바뀜** → 같은 장면 |

1. 불변성이 없으면 "북향 우회전"과 "동향 우회전"을 **따로** 배워야 합니다 → 데이터를 그만큼 낭비하고, 학습에서 못 본 방향에서 무너집니다
2. 엄밀히는 두 성질이 섞여 있습니다 — 내부 표현은 **안 변해야**(invariance) 하고, 출력 궤적은 장면과 **같이 돌아야**(equivariance) 합니다. 보통 묶어서 **SE(2) 불변성**이라 부릅니다
3. ⚠️ **두 방식 다 불변합니다.** "A는 불변이고 B는 아니다"가 아니라, 갈리는 건 **공통 좌표계가 있느냐**입니다

| | **Group A** (구조적) | **Group B** (정규화) |
| --- | --- | --- |
| 공통 좌표계 | **없음** — 차마다 자기 프레임 | **있음** — focal 차 기준 하나 |
| 각도를 어떻게 쓰나 | 기준이 없어 **쌍별 차이만** | 프레임이 고정돼 **각도값 그대로** |
| focal 의 우회전 | 항상 같은 모양 | 항상 같은 모양 |
| **주변 차의 우회전** | **항상 같은 모양** | ❌ 그 차가 보는 방향마다 숫자가 달라짐 |

   → **A는 θ를 만들 수밖에 없어서 이미 갖고 있고, B는 만들 필요가 없어서 안 갖고 있습니다.** SIMPL이 모든 차를 동시에 예측하는 모델이라 "주변 차까지 정규화되는가"가 크게 작용합니다
4. **핵심은 θ 가 바로 그 "상대각" 자체라는 점입니다** — θ = h − k 는 내 진행방향에서 차로 접선각을 뺀 값이고, 이건 Group A 가 불변성을 얻으려고 **이미 계산해 넣고 있는 양** 그 자체입니다

![invariance 두 그룹](../viz/meeting_1029/m2_invariance.png)

AV2 SOTA 7개(QCNet · SIMPL · Forecast-MAE · DeMo · HPTR · ProphNet · GANet)를 입력 채널 단위로 봤고, **불변성을 어디서 얻는가** 로 두 그룹이 갈렸습니다.

1. **Group A(구조적 불변)** 는 θ = h − k 를 **이미 attention 입력으로 갖고 있습니다.** QCNet 은 지도를 50 step 전체에 복제해 timestep 마다 `orient_pl − head_s`(= −θ)를 계산합니다
2. **Group B(정규화)** 는 장면을 한 번 회전시킬 뿐이라 상대 **각도**가 없습니다. **θ 가 진짜 새 정보인 곳은 여기**입니다
3. 문제는 **역상관** 입니다 — (a, h) 교체가 쉬운 모델일수록 θ 가 덜 보탭니다. 한 모델에서만 재면 *“θ 가 안 듣는다”* 와 *“그 구조엔 이미 있다”* 를 구별할 수 없습니다
4. 그래서 역할을 나눕니다 — **SIMPL = (a, h) 가설의 주 무대**, **Forecast-MAE = θ 가설의 처치군**
5. 실제로 fork 가능한 것은 넷뿐입니다. ProphNet·GANet 은 **코드가 공개된 적이 없고**(GANet 저장소는 1바이트 placeholder 4개), QCNet 은 학습에 **GPU 메모리 약 160 GB**, HPTR 은 **CC BY-NC**(비상업)입니다

## 3. 무엇을 넣을 것인가 — (a, h) 2채널 + 지도(기존 방식)

![θ = h − k 실례](../viz/meeting_1029/m3_theta.png)

위 그림은 **모델 없이 AV2 원본 데이터만으로** 그린 것입니다 — 좌회전 한 판에서 h(차량 진행방향) · k(최근접 차로 접선) · θ · a 를 그대로 뽑았습니다.

1. **θ 는 “차로가 꺾이는 몫”을 뺀 나머지입니다.** 93° 회전이 θ 로는 중앙 3.4° 로 접힙니다 — 예측해야 할 각의 크기가 한 자릿수로 줄어듭니다
2. **단 k 의 정의에 민감합니다.** 최근접 차로 규칙은 교차로에서 차로가 바뀌는 순간 k 가 **14°/step 튀고**, θ 가 그 튐을 그대로 받습니다(가운데 패널의 −34° 골). v4 에서 보던 문제가 여기서도 그대로 나옵니다
3. **AV2 는 가속도를 주지 않습니다** — parquet 컬럼은 `position · heading · velocity · object_type` 뿐이라, `a` 는 속도에서 유도합니다. 11초 창 양 끝 0.5초의 **속도 램프**가 경계에서 `a` 를 오염시킵니다
4. **그래도 2채널로 충분합니다.** 우리 `a` 는 일반적인 가속도가 아니라 **속도 증분이고 첫 값이 v₀** 라, 누적합하면 속도가 돌아옵니다. 실측으로 **(a, h) 만 적분해 과거 5초 궤적이 중앙 0.56 m(p90 1.28 m)** 로 복원됩니다 — 원래 의도대로 "모델이 (a,h) 에서 과거를 스스로 뽑아낼" 정보가 실제로 들어 있습니다
5. ⚠️ **첫 step 을 버리면 v₀ 가 통째로 날아갑니다.** SIMPL 이 50 step 중 앞 2개를 조용히 버리므로(`actors[..., 2:]`), (a,h) 인코딩은 **그 trim 이후 48 step 위에서** 만들어야 합니다

**지도는 기존 방식 그대로입니다** — `actor_gather` 한 곳에서 변위 Δp(2)와 velocity(2)를 빼고 a(1)를 넣어 **14채널 → 11채널**이 됩니다. 차로 그래프, agent 의 현재 pose(`TRAJS_CTRS`·`TRAJS_VECS`), 그 둘로 만드는 RPE 는 전부 원본입니다. 즉 **agent 가 지도 위 어디에 어느 방향으로 있는지는 그대로 남고**, 사라지는 것은 과거 5초의 움직임 중 (a,h) 이외의 것뿐입니다. 재전처리도 필요 없습니다.

## 3.5 예측이 어떻게 이루어지나 — 우리만 좌표가 아니라 "행동"을 냅니다

![예측 방식 비교](../viz/meeting_1029/m6_rollout.png)

디코더가 **미래 60 스텝의 (a, Δθ)를 한 번에** 내고, 그걸 적분해서 좌표를 만듭니다.

```
a  = 8.0·tanh(·) [m/s²]        Δθ = 8°·tanh(·) 스텝당
v  = relu(v0 + Σ a·dt) ≤ 40    θ  = θ0 + Σ Δθ,  |θ| ≤ 90°
s  = s0 + Σ v·cos θ·dt         차로를 따라 간 거리
d  = d0 + Σ v·sin θ·dt         차로에서 옆으로 벗어난 거리
(x, y) = P(s) + N(s)·d
```

1. **잔차각을 값이 아니라 변화율로 냅니다** — 스텝당 |Δθ| ≤ 8°라, **어떤 출력을 내도 요레이트가 물리 한계 안**입니다
2. **순차 루프가 없습니다** — 전부 누적합이라 **학습 경로와 추론 경로가 같고**, exposure bias가 구조적으로 0입니다
3. 좌표는 **회귀 대상이 아니라 적분의 결과**입니다

| 모델 | 무엇을 출력하나 | 구조로 보장되는 것 |
| --- | --- | --- |
| QCNet · Forecast-MAE · DeMo | 좌표 60개를 직접 | **없음** |
| **SIMPL** | **Bezier 제어점** → 곡선을 샘플링, 속도는 해석적으로 | **매끄러움** (운동학은 아님) |
| **우리** | **(a, Δθ) 60쌍** → Frenet 적분 | **가속도·요레이트·속도 부호 전부** |

**SIMPL이 가장 가까운 형제입니다** — "매끄러운 파라미터화를 내고 운동학을 유도한다"는 설계가 이미 같아서, (a, Δθ) 헤드는 이식이 아니라 **형제 재파라미터화**입니다. 디코더에 이미 `param_out` 스위치가 있어 네 번째 분기로 들어갑니다.

> ⚠️ **다만 R2 설계에 미해결이 하나 있습니다.** 지금 적분기는 기준선 하나를 **고정**해 놓고 s·d를 누적합으로 냅니다. k를 최근접 차로로 바꾸면 기준선이 매 스텝 달라져 **누적합이 깨지고 순차 루프가 생깁니다**(그러면 위 2번의 이점도 사라집니다). 선택지는 ① 기준선을 t=49의 최근접 차로 하나로 고정 ② 매 스텝 재투영하고 루프를 받아들임 — **아직 정하지 않았습니다.**

## 4. “5 Hz 다운샘플링이 과적합을 막아 주는가”

![레이트 문헌 공백](../viz/meeting_1029/m4_rate.png)

1. **레이트를 고정 길이에서 바꾼 통제 ablation 은 공개 문헌에 없습니다.** 독립 검색 4회가 같은 결론에 닿았습니다 — 이 공백 자체가 기여가 될 수 있습니다
2. **길이** 는 답이 뚜렷합니다 — AV2 history 의 마지막 1초는 값이 없습니다(QCNet 4 s 0.725 vs 5 s 0.726)
3. 가장 가까운 연구(E2E driving)가 제시한 기전은 **과적합이 아니라 capacity** 입니다. 그 틀대로면 효과는 작은 모델(Forecast-MAE 1.9 M · SIMPL 2.6 M)에서만 보여야 합니다
4. 반대 증거도 적지 않고, **우리 실측에서도 10 Hz → 2 Hz 는 3 seed 모두 나빴습니다(+0.072)**
5. → **이번 실험은 각 SOTA 모델의 기본 레이트를 따릅니다.** 레이트는 별도 ablation 축으로 두고, 재게 되면 capacity 축과 묶어서 잽니다

## 5. 그래서 무엇을 할 것인가

![SIMPL 검증과 단계](../viz/meeting_1029/m5_plan.png)

1. **단계 0 완료** — SIMPL 배포 체크포인트를 우리 환경에서 val 전수(24,988판) 재평가해 **minADE6 0.777**, 저자 보고치와 소수 셋째 자리까지 일치했습니다(175초). 전처리 캐시·평가 경로·모델 로딩이 저자 설정과 같다는 뜻입니다
2. 다음은 **R0(원본 입력) → R1((a, h) 2채널 + 지도 기존 방식)**, 같은 seed 로 각 45시간. **R1 − R0 이 이번 분기의 핵심 수치**입니다
3. 2조건 × 3 seed 를 미리 돌리면 270시간이라, **단계적으로 가고 차이가 애매할 때만 seed 를 붙입니다**
4. 비용은 줄일 여지가 거의 없습니다 — GPU 사용률 중앙 88 %, 로더 대기 0.2 %, backward 65 % 로 **연산 바운드**입니다. batch·workers·bf16 전부 효과 없었고 `torch.compile` 은 가변 길이 입력에서 실패했습니다. 참고로 논문의 "8×3090 11시간"은 88 GPU-시간입니다
5. **정성 평가는 정량과 같이 갑니다** — 상황 군집 8개의 대표 사례를 같은 시나리오 좌우 배치(원본 입력 / (a,h))로 두고, 지도 위에 정답 · 1위 궤적 · 최근접 차로 접선을 겹칩니다. 진단 패널은 heading(t) · 회전량 순/총 · |Δψ| 분포 · θ 분포 넷입니다

## 결정이 필요한 것

1. ~~R1 의 입력을 (a, h, v₀) 로 할 것인지~~ — **해결됨.** `a` 가 속도 증분이라 v₀ 가 a[0] 에 이미 실려 있습니다(위 3절 실측). **2채널 + 지도로 확정**합니다
2. **θ 가설까지 이번 분기에 볼 것인지** — 보려면 Forecast-MAE 판(+45시간)이 필요합니다. SIMPL 에서 θ 가 안 들어도 "효과 없음"이 아니라 "이미 있음"일 수 있습니다
3. **R2 의 적분기 기준선을 고정할 것인지 매 스텝 재투영할 것인지** — 3.5절의 미해결. 고정하면 exposure bias 0 이 유지되고, 재투영하면 차로를 더 정확히 따라갑니다
4. **k 를 최근접 차로로 둘 것인지** — 3절의 튐이 그 대가입니다. 후보 경로 열거를 되살리면 튐은 줄지만 v4 의 오라클 1.079 m 병목이 돌아옵니다

## 확인하지 못한 것

1. SIMPL 파라미터 수 — 논문 1.9 M vs 공개 체크포인트 실측 **2,646,481**. 원인 미상
2. Forecast-MAE 의 논문 val(0.801) vs README val(0.7117) 약 10 % 차이
3. "Recover to Predict" 의 `-Ori`/`-IT` 정의 — 표에서 추정했고 원문 확인 못 함
4. DeMo 의 Mamba 가 sm_120(우리 GPU)에서 빌드되는지
5. **SIMPL 의 seed 잡음은 측정한 적이 없습니다** — 판정 기준의 "0.05" 는 v4 수치를 빌려 쓴 것입니다
