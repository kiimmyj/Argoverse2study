# v4 정리 — 메인 아이디어부터 현재까지

> Argoverse 2 Motion Forecasting · 복습용 한 장 정리 · 2026-10-06 기준
> 세부 수치·실험 기록은 `v4` 상세 페이지들에 있음. 이 페이지는 **큰 줄기만** 담음.

---

## 1. 메인 아이디어

**"미래 위치를 직접 찍지 말고, 지도가 아는 것과 모르는 것을 나눠라."**

| 나눈 축 | 지도가 주는 것 | 모델이 배우는 것 |
| --- | --- | --- |
| **방향** | `k` — 도로가 휜 만큼 | `θ` — 차체가 도로보다 더 틀어진 만큼 |
| **선택지** | 후보 경로 K=6개 (어느 갈림길로 갈 수 있는가) | 그 경로 위에서 어떻게 움직일 것인가 |
| **출력 형식** | Frenet 적분기 (학습 파라미터 없는 고정 함수) | 액션 (a, Δθ) 60 step |

```
h  =  k  +  θ            예측 mode = 지도에서 열거한 후보 경로 K = 6
      ↑     ↑
   지도가   모델이
   준다     배운다
```

- 모델은 **좌표를 직접 출력하지 않음** — (a, Δθ)를 내면 적분기가 경로 위에서 좌표로 복원함
- 그래서 역주행·도로이탈을 **손실이 아니라 출력 형식이** 1차로 막음
- **대가가 있는 설계임** — 출력 공간을 규칙으로 좁히므로 minADE6는 올라감. 산 것은 실현가능성과 규칙 준수임
- 정직하게 — AV2 리더보드 상위권(QCNet, MTR++, Wayformer)은 전부 위치를 직접 회귀함. **downstream이 planner면 이 거래가 맞고, 리더보드 순위가 목표면 다른 선택이 나음**

## 2. `h = k + θ` — 각각이 무엇인가

| 기호 | 정의 | 단위 | 누가 주나 |
| --- | --- | --- | --- |
| **h** | 차량의 **이동 방향 각도** (velocity vector의 각도) | rad | 관측 위치를 차분해서 **직접 만듦** |
| **k** | 후보 경로 위 거리 `s`에서의 **차로 중심선 접선 각도** | rad | **HD map** |
| **θ** | `h − k` — 도로 방향 대비 차가 틀어진 각 (residual angle) | rad | **모델** |

### 2.1 h를 AV2 라벨에서 그냥 쓰지 않는 이유

- AV2의 `heading`은 **차체 방향(yaw)**이라 실제 이동 방향과 slip angle만큼 어긋남. 저속에서는 잡음이 크고 180° 뒤집힘도 있음
- 방향만 바꿔 궤적을 복원했을 때 최종 오차로 비교함

| h 만드는 법 | 복원 오차 |
| --- | --- |
| AV2 heading 그대로 | 1.693 m |
| **위치 차분 + 1 m/s 미만만 AV2로 보충** (채택) | **0.145 m** |

- **관측 구간(과거 5초)만 씀** — 차분은 다음 위치를 보므로 미래까지 넣으면 첫 예측 대상이 입력에 새어 들어감

### 2.2 왜 쪼개나

- `h`는 도로 방향을 따라 **360° 전체에 퍼져 있음**. `θ`는 **0 근처에 몰려 있음**(경로 기준 ±10° 이내가 91.9%)
- 6초 동안 따라가야 할 변화량도 `|Δh|` p90 52.8° → `|Δθ|` p90 14.6°로 줄어듦
- 즉 **방향 변화의 약 2/3를 지도가 대신 설명함**. 모델은 나머지만 배우면 됨

### 2.3 원 설계(곡률)에서 바뀐 것

- 미팅 9/3의 원안은 **곡률 레벨** `κ = κ_lane + δ`였음
- **각도 레벨** `h = k + θ`로 올렸음 — 적분이 한 단계 줄어 작은 편향이 거리에 따라 누적되지 않고, 원시 중심선에서 뽑은 곡률은 잡음이 큼(p99 0.379 1/m)
- `κ`와 `k`는 다른 양임 — `κ = dk/ds`

## 3. 모델 구성

```
[preprocessing]  입력 (a, h) 50 step · 주변 차로 20개 · 후보 경로 K=6
        │
        ▼
┌─────────────────────────────────────────────────────┐
│ Encoder                                             │
│   (a, h) 50×2  →  LSTM 2층(hidden 128)  → 궤적 feature │
│   + cross-attention ◄── 차로 token 20개              │  ◄── L2
│   (+ attention pooling ◄── 주변 차량 32대)            │  ◄── 2026-09-30 추가
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│ Decoder — mode K=6, 각각 독립                         │
│   mode 입력 = [궤적 feature, 경로 r embedding, 복제 번호] │  ◄── L3
│   출력 = (a, Δθ) × 60 step  +  mode 확률 logit        │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│ Frenet integrator f — 미분 가능, 누적합만, 학습 파라미터 0 │  ◄── L0
│   v = v0 + Σ a·dt                                    │
│   θ = θ0 + Σ Δθ            (|Δθ| ≤ 8°/step)          │
│   s = s0 + Σ v·cosθ·dt,   d = d0 + Σ v·sinθ·dt       │
│   h = k_r(s) + θ                                     │
│   p = 경로 r 중심선(s) + 법선 × d                      │
└──────────────────────┬──────────────────────────────┘
                       ▼
  Loss = smoothL1(승자 mode) + CE(mode 확률)
         + jitter penalty (모든 mode)        ◄── L0
         + off-lane hinge (버려진 mode만)     ◄── L4
```

- 파라미터 **450,681** (2채널 입력). 주변 차량 입력을 켜면 556,153

### 3.1 입력 feature — 왜 (a, h)인가

| 채널 | 무엇 |
| --- | --- |
| **a** | 속도 증분 [km/h] ÷ 3. 첫 값에만 관측 시작 시점의 속도를 싣고 나머지는 증분임. 누적합하면 속도 곡선이 복원됨 |
| **h** | 2절의 이동 방향. 마지막 관측 시점 기준으로 회전·정규화함 |

- 위치(x, y) 대신 **운전 조작 단위**로 바꾼 것임 — 2026-08-27 실험에서 위치 기반 5채널 → 조작 기반 표현으로 바꾸니 minADE6가 4% 좋아졌음
- 10 Hz(50 step)가 기본임. 2 Hz(10 step) 판도 만들었으나 6~7% 나빠 채택하지 않았음

### 3.2 HD map을 어떻게 입력에 넣는가

지도는 **두 경로로 들어감**. 역할이 다름.

**(가) 주변 차로 20개 — "어떤 도로 위에 있는가"**

| 항목 | 내용 |
| --- | --- |
| 선택 | focal 기준 가까운 순으로 20개 |
| 기하 | 중심선을 호길이 등간격 **10점**으로 리샘플, focal 정규화 프레임 좌표 → `10 × 2 = 20` |
| 규칙 feature | **10채널** → 진행방향 단위벡터 (dx, dy) · 같은 방향 여부 · 교차로 내부 여부 · 차로 종류 3개(차량/버스/자전거) · 좌측 차선변경 가능 · 우측 차선변경 가능 · 도달 가능 |
| embedding | 차로 1개를 `20 + 10 = 30`차원으로 펴서 `Linear(30→128) → ReLU → Linear(128→128)` |
| 융합 | 궤적 feature를 **query**, 차로 token 20개를 **key/value**로 하는 MultiheadAttention(4 heads) |

- 규칙 feature가 핵심임 — 좌표만 주면 "저 차로가 역주행인지, 지금 거기로 갈 수 있는지"를 모델이 다시 추론해야 함

**(나) 후보 경로 K=6 — "어느 갈림길로 갈 것인가"**

| 단계 | 내용 |
| --- | --- |
| 출발 | 현재 위치 5 m 안의 같은 방향 차로 |
| 연결 | **successor만** 이어 차로 사슬을 만듦 (U턴 제외) |
| 정렬·중복 제거 | 관측 궤적과 가까운 순. 6초 지평에서 2.5 m 안에 겹치면 같은 분기로 보고 버림 |
| 표현 | 호길이 등간격 **64점**의 좌표 2 + 접선 2 + 허용 밴드 2, 그리고 경로 길이 1 → `64 × 6 + 1 = 385`차원 |
| embedding | `Linear(385→128) → ReLU → Linear(128→128)` |
| 경로가 없을 때 | 직진 가상 경로 1개 (val의 3.8%) |

- **차선변경을 기하로 이어 붙이지 않는 이유** — 이음매가 접혀 θ가 180° 뒤집힘. 차선변경은 이웃 차로에서 시작하는 **별도 경로**나 횡오프셋 `d`로 표현함
- 구별되는 경로가 R개뿐이면 6칸을 돌려 채우고, 같은 경로에 배정된 슬롯은 **복제 번호 embedding**으로 구별함 (직선 도로에서 mode가 통째로 붕괴하는 것을 막는 축)

### 3.3 mode = 후보 경로인 이유

- 익명 mode는 갈림길에서 **두 길의 평균**을 냄 (T자 교차로에서 48° 비스듬히 가로지름)
- 다중 mode는 지도에 실제로 있는 **이산 선택지**여야 함
- 빈 칸은 확률을 −∞로 막음

### 3.4 Frenet integrator가 주는 것

| 효과 | 내용 |
| --- | --- |
| `d`가 상태 변수로 직접 나옴 | 차로 이탈 벌점(L4)이 단순해짐 |
| `h = k + θ`가 정의대로 성립 | 분해가 출력까지 일관됨 |
| 순차 루프가 없음 | 누적합뿐이라 학습·추론 경로가 같음 (v1이 발산한 원인을 구조적으로 배제) |
| `|Δθ| ≤ 8°/step` | 어떤 출력을 내도 yaw rate가 물리 한계 안에 있음 |

### 3.5 벌점 두 가지 — 구분해야 함

| 벌점 | 레벨 | 무엇을 | 어느 mode에 |
| --- | --- | --- | --- |
| **jitter** | L0 | 액션이 매 스텝 부호를 뒤집는 진동 | 살아있는 **모든** mode |
| **off-lane** | L4 | 중심선 횡거리 `d`가 **밴드 밖으로 나간 거리** | **버려진 mode만** |

- 밴드는 기본 ±1.75 m, 차선변경 가능·교차로·경로 없음이면 ±3.6 m
- **밴드 안에서는 어디에 있든 0임** — 중심으로 끌어당기면 편도 2차선에서 중앙선이 최적해가 됨 (미팅 9/3의 "가점을 center point로?" 질문에 대한 답임)
- **버려진 mode만 벌하는 이유** — 승자는 거리 손실이 이미 감독함. 정답 궤적조차 14% step이 밴드를 넘어, 승자에 걸면 잘못된 벌점만 늘어남

## 4. v1 → v4 흐름 (미팅 날짜 기준)

### 4.1 버전별 성적

| 버전 | 구조 | minADE | minFDE |
| --- | --- | --- | --- |
| v1 | LSTM Seq2Seq (autoregressive + teacher forcing) | **발산(폐기)** | — |
| v2 | LSTM encoder + MLP head (미래 60 step 한 번에 출력) | 3.17 | 8.26 |
| v2 + K=6 | multimodal 6궤적 (winner-takes-all) | 1.53 | 3.51 |
| **v3** | K=6 + HD map + MultiheadAttention | 1.32 | 2.95 |
| **v3 + 규칙** | + 차로 이동 규칙 feature (**v4의 기준선**) | **1.292** | 2.883 |

> 위 5줄은 **val 2,000** 기준임. 아래 v4 수치는 **val 24,988**이라 직접 비교하면 안 됨

| v4 단계 | 무엇을 더했나 | minADE6 (val 24,988) |
| --- | --- | --- |
| L2 | 지도 cross-attention | 기준선 재현 |
| L3 | mode = 후보 경로 | ↑ (설계상 정상) |
| L0 | 출력 = 액션 + Frenet 적분기 + jitter penalty | ↑ |
| L4 | + 차로 이탈 hinge | ↑ |
| **현재** | L4 · (a,h) · 전체 데이터 · 30 epoch cosine · action penalty 1.0 | **1.440** (3 seeds 평균, best seed 1.402) |
| **검토 중** | 같은 조건 · **coordinate penalty 1.0** | **1.359** |

- **v1이 발산한 원인이 이후 설계의 기준임** — 학습(teacher forcing = 정답 커닝)과 평가(자기 예측)의 불일치로 오차가 60 step 누적됨. v2가 decoder를 없애 한 번에 출력하면서 해결됐고, **v4의 적분기도 순차 루프가 없음**
- 클래스명은 v1~v3 모두 `LSTMSeq2Seq`지만 진짜 seq2seq는 v1뿐임 — 이름으로 구조를 추측하면 안 됨

### 4.2 미팅별로 무엇이 들어왔나

| 날짜 | Action Item (AV2 관련) | 무엇이 됐나 |
| --- | --- | --- |
| **8/6** | v3 = HD map, v4 = (a, h)로 데이터 구성. 리포트는 minADE + HD map 위 궤적 plotting | v3 착수. v4의 방향이 이때 정해짐 — **좌표가 아니라 운전 조작으로 표현한다** |
| **8/13** | v3 — 연결 불가능한 차로 미리 제거, 지도와 좌표를 동시에 예측하는 구조 | 차로 선택 20개 + 규칙 feature의 뿌리임. "연결 가능성"이 **도달 가능 플래그**로 들어감 |
| **8/20** | v3에 차로 간 이동 규칙(U턴, 차로변경) 보완. v4 — (x, y) → (a, h) 변환 함수. horizon은 5~6초 고정 | 변환 함수 = `heading_decomp`. horizon 6초(60 step) 고정은 지금도 유지 중임 |
| **8/27** | v4 — 변환 함수, 모델링, **map을 어떻게 input으로 넣을지** | 표현 비교 실험 수행 — 조작 기반 표현이 위치 기반보다 4% 좋았고, 가속도만 쓰는 2채널은 6.7% 나빴음. map 입력 질문의 답이 3.2절의 **두 경로(차로 token + 후보 경로)**임 |
| **9/3** | heading의 의미 정확히 확인. `phi = kappa + theta` 분해. 벌점은 이탈에 주되 가점 기준이 중앙선 방향인지 center point인지. epoch당 시간 측정. 1 scenario = 1 train data | **v4의 핵심이 이날 정해짐.** heading = 차체 방향임을 확인하고 이동 방향 `h`를 따로 만들기로 함. 분해는 곡률 대신 **각도 레벨**로 올림(2.3절). 가점 질문의 답은 **밴드 안 0인 hinge**임(3.5절). epoch 시간 계측과 1 scenario = 1 sample은 그대로 적용 중임 |
| **9/10** | penalty term을 L0~L4와 묶기. phi 이용 input 학습 + 중간 체크포인트 + 회전 시나리오 visualization. preprocessing(smoothing, DS) 병렬 | 벌점을 레벨에 묶음 — **jitter는 L0, off-lane은 L4**. 중간 체크포인트 저장(`--save-every`)과 epoch별 분석 도구가 이때 생김. **φ(=θ) 입력 추가는 아직 안 함 (열린 항목)** |
| **9/17** | 벌점 필요성 + 논문. preprocessing. neighborhood vehicle. U턴/차로변경. 데이터 cleansing. visualization framework | 전부 `v4_notion_penalty_to_now` 페이지에서 답함 — 벌점은 **필요하되 target을 좌표로 바꿔야 함**, 주변 차량 radius 30 m 구현, 차선변경 원인은 **횡 mode 축 부재**, cleansing은 **폐기가 아니라 보정** |

## 5. 지금 상태와 열린 문제

**확정된 것**
1. 방향 분해는 각도 레벨 `h = k + θ`임
2. mode는 지도에서 열거한 후보 경로임
3. 출력은 액션 (a, Δθ), 좌표 복원은 Frenet 적분기임
4. 벌점은 두 가지 — jitter(L0, 모든 mode) · off-lane(L4, 버려진 mode만)
5. 비교는 **paired-seed**로 함. 단일 seed 차이는 효과로 읽지 않음

**열린 문제**
1. **벌점 target 전환 여부** — coordinate penalty 1.0이 정확도 손해 없이 위반율을 0.29배로 낮춤. 기본값 교체를 검토 중임
2. **φ(= θ)를 입력에 추가** — 9/10 Action Item인데 아직 안 함
3. **5채널 입력 기준선 없음** — (a, h) 입력 효과만 따로 떼지 못함
4. **차선변경** — 횡 mode 축을 구현했으나 전체 지표로는 효과가 검출되지 않음. 627건 전용 평가군 필요
5. **주변 차량** — 구현했으나 전체 지표로는 검출 불가. 309건 전용 평가군 필요
