# v4 — 지도를 아는 궤적 예측

> Argoverse 2 Motion Forecasting · 한 페이지 누적 정리 · 최종 갱신 2026-09-14
> 이 페이지는 단계가 끝날 때마다 갱신된다. 상세는 각 단계의 리포지토리 문서에 있다.

---

## 0. 한 장 요약

**"미래 위치를 찍지 말고 지도가 아는 것과 모르는 것을 나눠라."**

방향을 `h = k + θ` 로 쪼갠다 — `k`(도로가 휜 만큼)는 **지도가 주고**, `θ`(차체가 더 휜 만큼)만
**모델이 배운다**. 예측 모드도 학습된 익명 슬롯이 아니라 **지도에서 실제로 열거된 경로**로 바꾼다.

```
h  =  k  +  θ          예측 모드 = 후보 경로 K개
      ↑     ↑
   지도가   모델이       "어느 갈림길로 갈 것인가" 를 지도가 이산 선택지로 준다
   준다     배운다
```

### 현재 성적

| 단계 | 무엇 | minADE6 | minFDE6 | 밴드 이탈 | dθ p99 |
| --- | --- | --- | --- | --- | --- |
| — | 기준선 (v3 + 차로 규칙 피처) | **1.292** | 2.883 | — | — |
| **L2** | 지도 cross-attention (하네스 재현) | 1.292 | 2.883 | — | — |
| **L3** | 모드 = 후보 경로 | **1.414** | 3.153 | — | — |
| **L0** | 출력 = 액션 (a, θ) + Frenet 적분기 | 1.666 | 3.957 | 1.35 | **7.0°** |
| **L4** | + 이탈 hinge (버려진 모드) | **1.756** | 4.147 | **0.71** | 8.0° |
| **L0 · (a,h)** | 입력 (a, h) 2채널 + θ₀ 가드 | 1.593 | 3.783 | 1.56 | 6.3° |
| **L4 · (a,h)** | 입력 (a, h) 2채널 + θ₀ 가드 + 이탈 hinge | 1.705 | 3.947 | 0.90 | 8.0° |

> (a, h) 두 줄이 위 L0·L4 보다 좋아 보이는 건 그 사이 적분기 기하가 고쳐졌기(`bbefc60`) 때문이다.
> 같은 코드로 다시 재면 정확도는 비슷하거나 조금 나쁘고, 실현가능성은 좋아진다 — 2.4절.

**minADE6 이 1.292 → 1.756 (+36%) 로 올라가는 것이 설계상 정상이다.** 출력 공간을 규칙으로
좁히면서 실현가능성·규칙 준수를 사는 거래이기 때문이다. 가격표:

| 산 것 | 판 것 |
| --- | --- |
| 라벨 상한(7.3°/step) 초과 step **71.4% → 0.4%**(L0b) / **4.4%**(L4_nw, 최종 채택 모델) | minADE6 +36% |
| 밴드 이탈 **50% 감소** (최근 5에폭 평균 1.39 → 0.70 — 위 표의 1.35/0.71 은 best 에폭 값이다. '밴드 이탈' = 시나리오당 유효 모드별 '밴드 밖 step 비율' 의 합, 범위 0~6) | minFDE6 +44% |
| 모드가 지도의 실제 분기가 됨 (평균 세탁 방지) | |
| 역주행 0.56% → **0.11%** | |

**이 표는 minADE6 단독으로 읽으면 안 된다.**

## 1. 왜 이 거래인가

| 사는 것 | 파는 것 |
| --- | --- |
| 실행 불가능한 궤적 26% → 0% *(Cui et al. ICRA 2020 — 다른 데이터셋의 선행 연구 수치, 이 프로젝트 실측이 아니다)* | minADE 약간 |
| 6초 heading 오차 7.69° → 4.92° *(같은 논문 인용값)* | 리더보드 순위 |
| 역주행·도로이탈을 **출력 형식이** 막음 | |

`minADE` 는 실현가능성을 재지 않는다. 정답에 가깝기만 하면 물리적으로 불가능해도 점수가 좋다.
예측을 사람이 그림으로 보는 게 아니라 **플래너가 입력으로 받는다면** 실행 불가능한 26% 는 치명적이다.

> 정직하게 — AV2 리더보드 상위권(QCNet, MTR++, Wayformer)은 전부 위치를 직접 회귀하고
> 액션 공간 지도 융합이 0이다. **다운스트림이 플래너면 이 거래가 맞고, 순위가 목표면 다른 선택이 낫다.**

## 2. 방향 표현 — `h = k + θ`

### 2.1 왜 각도 레벨인가

설계 문서의 원안은 곡률 레벨(`kappa = kappa_lane + delta`)이었다. 두 식은 같은 분해다:

```
h = k(s) + θ    를 호길이로 미분하면    dh/ds = kappa_lane(s) + dθ/ds
```

각도 레벨로 올리면 **적분이 한 단계 줄어든다.**

| | 곡률 레벨 | **각도 레벨** |
| --- | --- | --- |
| 잔차 편향의 영향 | δ 편향 0.005/m 가 60 m 누적 → heading 17° | **거리 따라 안 커짐** |
| 정지 차량 (step 의 14.5%) | s 가 안 늘어 곡률이 정의 안 됨 | heading 그대로 정의됨 |
| 실현가능성 | 출력 형식이 **구조적으로** 보장 | **Δθ 레이트 제한으로 직접 걸어야 함** ← 대가 |

마지막 줄이 실제로 물렸다 — 5절 참조.

### 2.2 `h` 는 AV2 heading 이 아니라 위치차분으로 만든다

AV2 `heading` 은 **차체 방향**이라 이동방향과 슬립각만큼 어긋난다. 방향만 바꿔 궤적을 다시
굴리면(스텝 길이는 원본 고정 → 오차 원인이 방향뿐):

| h 만드는 법 | 최종오차 | 보조 비율 |
| --- | --- | --- |
| 위치차분만 | **0.000 m** | 0% |
| **< 1.0 m/s 를 AV2 로 보조** | **0.145 m** | 15.5% |
| AV2 heading 그대로 | **1.693 m** | 100% |

기준속도 1.0 m/s 의 근거 — 저속에서 위치차분 방향이 무너지는 지점:

| 속력 | 위치차분 떨림 | AV2 떨림 | 판정 |
| --- | --- | --- | --- |
| < 0.5 m/s | **7~11°/step** (70~110°/s) | 0.03~0.09° | 차량 한계 밖 — 노이즈 |
| 0.5~1.0 | 2.97° | 0.20° | 의심스러움 |
| 1.0~1.5 | 1.81° | 0.42° | 실제 저속 회전으로 설명 가능 |

**1.0 m/s 는 물리적으로 불가능한 구간을 전부 걷어내는 가장 낮은 값**이고, 그때도 AV2 를
그대로 쓸 때보다 12배 정확하다.

> **이 결론이 학습에 들어간 건 늦었다.** 단계 1~4 의 v4 학습 입력은 전부 기준선 5채널
> `(x, y, vx, vy, h_AV2 − yaw0)` 였다. θ 입력 채널 A/B 에서 이득이 없어 입력을 고정하면서 heading
> 출처까지 **AV2 원본**으로 남았고, 그 채널은 wrap 도 없어 시나리오의 5.10% 에서 입력이 2π
> 점프했다. 적분기 시작값 θ₀ 도 AV2 차체 방향 기준이었다. 위치차분 heading 이 실제 학습 입력이
> 된 건 2.4절의 (a, h) 입력부터다(`b1db1a6`).

### 2.3 θ 의 실제 분포

| 기준 | 중앙 | p90 | ±10° 이내 |
| --- | --- | --- | --- |
| 최근접 차로 | 1.00° | 10.75° | 89.3% |
| **경로 기준** | 1.00° | **8.00°** | **91.9%** |

6초 동안 **따라가야 할 변화량**이 분해의 실익이다: `|Δh|` p90 **52.8°** vs `|Δθ|` p90 **14.6°**
— 지도가 방향 변화의 약 2/3 를 대신 설명한다.

### 2.4 v4 입력 — `(a, h)` 2채널 (2026-09-14)

사용자가 의도한 v4 구조는 **(a, h) 입력 → 모델이 (a, h) 형태로 예측 → 함수로 궤적 복원**이다.
출력과 적분기는 이미 `(a, Δθ) → h = k(s) + θ` 였고 입력만 5채널이었다. 그래서 입력을 바꿨다.

| 채널 | 무엇 | 왜 |
| --- | --- | --- |
| `a` | 속도 증분 [km/h] ÷ 3, **첫 값에 v0** | (a, h) 만으로는 초기속도가 빠져 궤적을 못 복원한다(v0 를 0 으로 두면 FDE 13.4 m). 첫 스텝에 v0 를 실으면 누적합으로 속도가 무손실 복원된다 |
| `h` | 위치차분 진행방향(1 m/s 미만만 AV2 보조), focal 정규화, wrap | 수치상 `k + θ` 와 같다. 지도는 모델이 따로 받으므로 k·θ 로 쪼개 넣지 않는다 |

두 채널 모두 **관측 50스텝만** 쓴다. `build_heading` 은 전방차분이라 110스텝을 넣으면 h[49] 가
첫 예측 대상 pos[50] 을 보는데, 이 누수는 시나리오의 57.7% 에서 h[49] 를 바꿨다(중앙 0.14°, p90 1.34°).

> 예전 파이프라인(v3 지도 모델, 규칙 피처 없음, 시드 1개)에서는 이 2채널이 5채널보다
> **6.7% 나빴다**(1.406 vs 1.318). 그 근거를 보고 난 뒤의 선택이다.

**검증**

| 항목 | 결과 |
| --- | --- |
| (a, h) 만으로 관측 5초 재구성 (val 300) | 중앙 0.000 m / p95 0.251 m |
| h 채널 ±π 점프가 있는 시나리오 (val 300) | **1.33%** (기존 5채널은 val 3,000 에서 5.10%) |
| 인과성 — 미래(t≥50)를 흔들고 `__getitem__` 통과 (val 150) | y 를 뺀 18개 필드 **비트 불변** |
| 기존 5채널 경로 회귀 (val 12 샘플 비트 비교) | 18개 필드 동일, 새 필드 `h0` 는 스칼라 |

**적분기 시작값 θ₀ — 가드가 필요하다**

기존 `θ₀ = −k(s0)` 는 정규화 프레임의 0 방향(= AV2 차체 방향)을 진행방향으로 본다. 그래서 슬립각만큼
어긋난다(|h0| 중앙 0.79°, p90 5.2°, p99 19.8°). 그렇다고 `wrap(h0 − k(s0))` 를 그대로 쓰면
θ 가 첫 스텝부터 ±90° 에 걸려 `ds = 0` 이 되고 **궤적이 옆으로 미끄러진다.**

| θ₀ | 90° 넘는 모드 (val 2,000 · 살아있는 모드 11,625) | 시나리오 |
| --- | --- | --- |
| `−k(s0)` (기존) | 48 (0.41%) | 20 |
| `wrap(h0 − k(s0))` | 151 (1.30%) | 44 |
| **가드** — 90° 안일 때만 새 값 | **44 (0.38%)** | **18** |

새로 90° 를 넘는 26개 시나리오 중 23개가 5 m/s 미만(저속 뒤집힘 판정·후진)이었다.

**θ₀ 규칙은 학습과 추론이 같아야 한다.** 기존 규칙으로 학습한 가중치에 추론 때만 가드를 붙이면
시작 오프셋이 60스텝 내내 남아 minADE6 이 7~8% 나빠진다(l0b 1.594 → 1.701). 이득은 재학습으로만 잴 수 있다.

> 검증 중 버그 하나 — 데이터셋에 이미 있던 `h0 = (cos θ, sin θ)` 방향벡터가 새 스칼라 `h0` 를
> 덮어써 필드가 `(2,)` 로 나갔다. 방향벡터도 관측값이라 인과성 검사로는 못 잡고, 학습 스모크에서 잡혔다.

**학습 결과** — L0·L4 의 (a, h) 판 2개만 돌렸다(사용자 결정, 50k / 15에폭, 시드 1개).

학습 로그만 보면 (a, h) 판이 좋아 보인다(L0 1.666 → 1.593, L4 1.756 → 1.705). **하지만 이건 입력 효과가 아니다.**
기존 체크포인트의 로그 값은 적분기 기하 수정(route_point, `bbefc60`) 전에 평가된 것이고, 같은 체크포인트를
현재 코드로 다시 재면 L0 1.594 / L4 1.682 가 나온다. 네 체크포인트를 모두 현재 코드로 굴린 비교
(val 2,000, `src/compare_v4_ah2.py`):

| | minADE6 | minFDE6 | 7.3°/step 초과 step | 밴드 이탈 | 첫 스텝 θ=±90° 모드 |
| --- | --- | --- | --- | --- | --- |
| L0 5채널 | 1.594 | **3.626** | 0.60% | **1.35** | 101 |
| L0 (a, h) | **1.593** | 3.783 | **0.15%** | 1.56 | **56** |
| L4 5채널 | **1.682** | **3.807** | 5.23% | **0.71** | 120 |
| L4 (a, h) | 1.705 | 3.947 | **3.36%** | 0.90 | **64** |

- **정확도는 나아지지 않았다.** minADE6 은 L0 에서 같고(−0.1%) L4 에서 +1.4%, minFDE6 은 두 판 모두 약 +4% 나쁘다.
  예전 파이프라인에서 2채널이 +6.7% 나빴던 것보다는 격차가 작지만 이득은 아니다.
- **실현가능성은 좋아졌다.** 요레이트 상한(7.3°/step)을 넘는 step 이 0.60% → 0.15%, 5.23% → 3.36% 로 줄었고,
  첫 스텝부터 ±90° 에 걸려 옆으로 미끄러지며 출발하는 모드가 절반 가까이 줄었다(101 → 56, 120 → 64).
- **차로 밴드 이탈은 늘었다** (1.35 → 1.56, 0.71 → 0.90).

이 비교도 입력만의 효과는 아니다. (a, h) 판은 θ₀ 가드와 새 기하로 **학습**됐고, 기존 판은 옛 기하로 학습된
가중치를 추론 때만 새 기하로 굴린 것이다. 입력 효과만 떼려면 5채널을 같은 코드·θ₀ 가드로 재학습한 기준선이 필요하다.

## 3. 전처리 — 후보 경로 열거기

`k` 는 기준 경로의 접선각에서 나온다. **경로가 틀리면 θ 라벨이 통째로 오염된다.**
그래서 먼저 열거기를 고쳤고, 결함이 둘 있었다.

### 결함 1 — 차선변경 이음매에서 경로가 180° 접힌다

| 경로가 쓴 이동 | 접힘 비율 |
| --- | --- |
| successor 만 | **0%** |
| 차선변경이 든 경로 | **98~100%** |
| 전체 | **55.4%** (val 1,459 · 열거된 경로 전수) |

이웃 차로는 현재 차로 **옆에서 처음부터** 시작하는데 중심선을 통째로 이어붙여서, 이음매가
중앙값 21 m 뒤로 접혔다.

### 결함 2 — 경로가 6초를 못 덮는다

`max_hops=4` 인데 AV2 차로 조각은 중앙 **약 20 m** 라 4홉이 약 80 m 다(val 80개 지도 5,391 차로 재측정: 중앙 20.6 m / 평균 23.9 m). 6초에 90 m 가는 차량은 경로 끝을
지나치고 `|d|` 가 최대 **102 m** 까지 커진다. **시나리오의 34.5%** 가 이 상태였다.

### 고침 — successor 만, 지평은 v0 로

**차선변경을 기하에서 빼는 이유**: 지도가 **전이 지점을 주지 않는다.** 어디서 차로를 바꿀지는
두 차로가 겹치는 구간 전체에 걸친 연속 자유변수라, 이음매 위치를 고르는 순간 지도에 없는 값을
기하에 박게 되고 그 전이 곡률(실제 커브의 3~7배)이 `k` 로 둔갑한다. **`h = k + θ` 는 `k` 가
도로만 담아야 성립한다.** 차선변경은 별도 succ-only 경로 + 잔차 `(d, θ)` 가 표현한다.

| 지표 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 하위호환(`legacy=True`) | — | **2,906/2,906 일치, 좌표 최대차 0.00e+00** |
| 접힘 >90° 경로 | 55.4% | **0.000%** |
| 자기되돌아옴 경로 | 16,814 | **0** |
| 6초 못 덮는 경로 | 11.7% | **2.0%** |
| 경로 0개 시나리오 | 2 | **0** |

> `경로 0개` 는 **시작 차로는 찾았는데 열거기가 경로를 못 만든** 경우다(val 1,459, 두 센터라인).
> `candidate_lanes` 가 시작 차로 자체를 못 찾는 경우는 별개이고 열거기 수정과 무관하다 —
> `simulate_v4_lane --limit 300` 기준 수정 전후 모두 4개, val 전체로는 3.75% 다.
| 경로 접선 꺾임 (중앙) | **118.9°** | **3.5°** |
| 역주행 (모드) | 0.56% | **0.11%** |
| 투영 후 minADE6 | 3.432 | **1.702** |

## 4. 출력 밴드 — 어디까지 벗어날 수 있게 할 것인가

succ-only 경로에서는 차선변경이 잔차 `d` 로 표현되므로 밴드 폭이 곧 **L0·L4 의 표현력 천장**이다.
(L3 는 경로를 조건으로만 쓰고 출력은 자유 위치 회귀라 밴드에 갇히지 않는다 — 아래 5절 참조.)

| 밴드 | recall@1 | recall@5 | 천장(@40) | 대가 |
| --- | --- | --- | --- | --- |
| ±1.75 (차로 반폭) | 63.9% | 77.9% | 79.7% | 없음 — 보장 최대 |
| **규칙 밴드 + 교차로 완화** | 72.0% | **87.4%** | **89.9%** | 규칙상 갈 수 있는 쪽만 열림 |
| ±3.6 평평 | 81.1% | **94.5%** | 96.6% | 밴드의 **27.6% 대향차로 / 21% 도로 밖** |

`±3.6` 만 문서 판정선(recall@5 ≥ 0.90)을 넘지만 **그 통과는 보장을 팔아서 산 것**이다. (표는 val 3,000 중 10 m 이상 이동한 2,380 시나리오 기준 — 전체로 보면 규칙 밴드는 85.2% 다. 즉 채택한 규칙 밴드는 판정선 **미달**이고, 원 설계 문서는 미달이면 L3·L0 를 포기하라고 했는데 그 지시를 따르지 않고 진행했다.)
이 설계를 고른 근거가 "실현 불가능 26% → 0%" 인데, ±3.6 으로 열면 출력 공간 자체가 역주행을 허용한다.
**규칙 밴드를 채택**했다 — 규칙상 차선변경이 허용된 쪽과 교차로 안에서만 넓힌다.

## 5. 레벨별 결과

### L2 — 지도 cross-attention

새 하네스가 기준선을 **소수점까지 재현**(1.292 / 2.883 / params 414,294)한다.
이후 차이는 전부 레벨 때문이다.

### L3 — 모드 = 후보 경로

처음엔 **+25% 나빠졌다**(1.616). 원인은 모드 붕괴였다:

| 지평에서 경로끼리 최대 거리 | 시나리오 비율 |
| --- | --- |
| < 1 m | **28.2%** |
| < 5 m | 46.0% |

직선 도로에는 갈림길이 없으니 모드 6개가 사실상 1개가 되고 `minADE6` 이 `minADE1` 로 퇴화한다.
익명 슬롯은 그 자리에서 **속도 프로파일**로 갈라져 있었는데 그 축을 없앤 것이다.

**고침**: 중복 경로를 제거하고 모드를 `(분기 × 종방향 하위모드)` 로 쪼갰다.
구별 분기 중앙 3개. → **1.414 (+9.5%)**, 퇴행의 62% 회수.

**남은 +9.5% 는 밴드 천장 탓이 아니다.** L3 는 `return head, logits, {}` 로 자유 xy 를
내놓고 `rollout`·`band` 를 거치지 않는다 — 밴드 천장은 L0·L4 의 제약이다. 직접 재보면:

| 구별 분기 수 | 시나리오 | 기준선 | l3b | 퇴행 | 몫 |
| --- | --- | --- | --- | --- | --- |
| 1 | 251 | 1.187 | 1.362 | +0.175 | 18.8% |
| 2 | 449 | 1.188 | 1.232 | +0.044 | 8.4% |
| 3 | 435 | 1.399 | 1.529 | +0.129 | 24.0% |
| 4 | 579 | 1.332 | 1.430 | +0.098 | 24.1% |
| 5 | 118 | 1.538 | 1.502 | −0.035 | −1.8% |
| 6+ | 168 | 1.136 | 1.507 | **+0.370** | 26.5% |

※ 6+ 행의 168개에는 지도 경로가 없는 75개가 섞여 있고, 그 75개는 l3b 를 부채꼴 폴백 데이터로
잘못 평가한 값이다. 실제 6분기 93개만 떼면 퇴행은 +0.310 이다.

- 분기 수와 퇴행의 **상관 +0.025** — 모드 기아 가설은 반증된다.
- 가장 큰 단일 덩어리는 **지도가 경로를 못 주는 75개**다. 폴백이 직진 하나뿐이라 `minADE1` 로
  채점됐다: 기준선 0.710 → l3b **1.326**, 퇴행 +0.616, 전체 격차(1.416 − 1.292 = 0.124 m)의 약 19%.
  처음엔 1.154 / +0.445 / 14.2% 로 적었는데, l3b 를 부채꼴 폴백 데이터로 평가한 방법 오류였다.
  이 버킷을 부채꼴 폴백으로 고치려던 시도는 실패했다(8절).
- 나머지 +0.104 는 **모드 예산을 지도 분기에 묶은 대가**로 읽힌다(6분기 버킷 +0.310).
- l3b 는 15에폭에서도 아직 내려가는 중 — **과소학습 가능성은 아직 확인 못 했다.**

### L0 — 출력을 액션으로, Frenet 적분기

데카르트가 아니라 **경로 좌표계에서 적분**한다. 속도벡터가 차로 접선과 이루는 각이 곧 `θ` 이므로

```
ds = v·cos(θ)·dt      dd = v·sin(θ)·dt      p = P(s) + N(s)·d
```

로 **`d` 가 상태 변수로 직접 나온다.** L4 는 그 `d` 에 hinge 를 거는 것으로 끝나고,
`h = k(s) + θ` 도 정의 그대로 성립한다. 누적합만 쓰므로 순차 루프가 없고 exposure bias 가 0이다.

**그런데 처음 구현은 설계의 간판 주장을 깨고 있었다.** 학습된 L0 의 스텝간 방향 변화:

| | 중앙 | p99 | 라벨 상한(7.3°) 초과 |
| --- | --- | --- | --- |
| 학습된 L0 `\|Δθ\|/step` | **17.91°** | **174.09°** (= 1741°/s) | **71.4% of step** |
| 실제 차량 (라벨 전수조사) | 0.05° | 2.75° (p99.99 = 7.3°) | — |

**step 의 71.4% 가 실제 차량이 낼 수 없는 것**이었다 (val 300). 이 값은 레이트 제한을 넣기
**전 코드**로 잰 것이라 현재 코드로는 재현되지 않는다 — 지금 체크포인트를 현재 코드에 얹으면
같은 원시 출력이 Δθ 로 재해석된다. 실행가능성 보장은 **곡률** 파라미터화에서
나오는데(방향이 유계 곡률의 적분), 각도 레벨로 올리면서 `θ` 를 스텝마다 독립으로 내게 만들자
보장이 사라진 것이다. 2.1절 표에 예고돼 있던 대가이고, **minADE 로는 절대 안 보인다.**

**고침** — `θ` 를 값이 아니라 **변화율**로 낸다: `θ_t = θ_0 + Σ (8°·tanh)`.
8° 는 라벨 정상값 상한 7.3°/step 근거. 이러면 어떤 출력을 내도 요레이트가 **라벨이 실제로 보이는 상한 수준** 안에 있다 (8°/step = 80°/s, 라벨 상한 7.3°/step = 73°/s — 앞서 든 '승용차 한계 ~50°/s' 기준은 아니다).

| | minADE6 | dθ p99 | 실현 불가능 step |
| --- | --- | --- | --- |
| 레이트 제한 없음 | 1.607 | 174.09° | **71.4%** |
| **레이트 제한 8°/step** | 1.666 | **7.0°** | **0.4%** (구조 상한은 8°/step 이라 7.3°~8.0° 구간이 열려 있다) |

제한이 minADE6 을 +3.7% 올린다. **그게 실현가능성의 값이다** — 1.607 은 실제 차량이 못 내는
궤적으로 얻은 점수라 비교 대상이 아니다.

### L4 — 차로 이탈 단측 hinge

벌점을 **모든 모드에** 거는가(문서 원안), **버려진 모드에만** 거는가를 나눠 돌렸다.
후자의 근거는 실측이다 — 기준 경로를 하나 고르면 정답 궤적의 14.05% step 이 벌점을 받고,
승자는 정의상 정답에 가장 가까워 거리 손실이 이미 옳게 감독하므로 오탐만 얹힌다.

에폭 선택 노이즈를 빼려고 **최근 5에폭 평균**으로 본다:

| | minADE6 (best / 최근5) | 밴드 이탈 (best / 최근5) |
| --- | --- | --- |
| L4 없음 | 1.666 / 1.722 | 1.35 / **1.39** |
| 모든 모드 | 1.826 / 1.885 | 0.64 / **0.68** |
| **버려진 모드만** | **1.756 / 1.791** | 0.71 / **0.70** |

- **L4 는 작동한다** — 밴드 이탈 **50% 감소**.
- **버려진 모드에만 거는 쪽이 같은 감소를 더 싸게 산다** — 이탈은 사실상 동률인데
  minADE6 이 **0.09 m 낮다.** 측정이 시사한 설계가 학습 결과로 확인됐다.

## 6. 도로 이탈 벌점 — 폴리곤이 아니라 차로 중심선

### 하면 안 되는 것

`drivable_areas` 폴리곤의 **중심축에서 벗어난 만큼** 벌주면 안 된다. 그 중심축은 편도 2차선에서
**정확히 중앙 이중황색선**이라, 세게 걸면 **정면충돌 차선이 최적해**가 된다.

### 하는 것

```
L4 = mean_t  max(0, d_t − band_left) + max(0, −d_t − band_right)
```

"중앙"이 두 개라 섞이기 쉽다:

| | 무엇의 중앙 | 벌점 |
| --- | --- | --- |
| **차로 중심선** | 차로 하나의 중앙 | 양측이어도 안전 — 실제로 있어야 할 자리 |
| 주행가능영역 중심축 | 도로 전체의 중앙 = 중앙선 | **걸면 역주행이 최적해** |

차로 기준으로 하면 **SDF 전처리가 통째로 없어진다** — `to_frame()` 이 이미 `(s, d)` 를 준다.

## 7. 문서의 주장 중 실측으로 뒤집힌 것

| 문서 주장 | 실측 |
| --- | --- |
| "L1(입력에 차선 상대량)은 정보 기여 0" | **반증 못 함.** θ 입력 채널 1.292 → 1.284 (−0.6%). 시드 1개뿐이라 "기여 0" 을 확정한 것이 아니라 "유의한 이득을 못 봤다" 가 정확하다 |
| "off-road 예측은 사실상 **전부** 버려진 모드에 있다" | **과장.** 있는 그대로 재면 승자 14.4% vs 버려짐 18.1% = **1.25배**(균등 83.3%와 구별 안 됨). 기준 경로를 믿을 수 있는 경우로 좁히면 2.8~3.5배로 방향은 맞지만, **승자도 시나리오의 9~13%에서 위반**한다 |
| "L3 후보 경로 열거기는 `lane_graph.py` 로 이미 있음" | **아니다.** 열거기는 `lane_frame.build_routes` 이고 경로의 55%가 깨져 있었다 |
| "모델이 무슨 값을 뱉든 나오는 궤적은 실행 가능하다" | **곡률 레벨에서만 참.** 각도 레벨에서 θ 를 스텝마다 독립으로 내면 궤적의 **71.4%가 실현 불가능**해진다. Δθ 레이트 제한을 직접 걸어야 회복된다 |

추가로 찾은 것:
- **기준 경로를 과거만으로 하나 고르면 정답 궤적의 14.05% step(시나리오의 28.7%)에 벌점이 걸린다.**
  위반량 중앙 2.1 m / p90 14.8 m — 차로를 살짝 벗어난 게 아니라 분기를 잘못 잡은 것이다.
  → L0 은 **모드마다 자기 경로**를 갖고 그 프레임에서 `d` 를 적분하므로 이 함정을 비켜간다.
- **기존 기준선의 방향 입력 채널에 `wrap` 이 없다** — `head - theta` 가 (−2π, 2π) 범위라
  **시나리오의 5.10%에서 입력이 2π 점프**한다. 커밋된 1.292 를 포함한 기존 결과 전부가 이 상태다.
  (레벨 비교는 모두 같은 입력을 쓰므로 유효. 4단계 후 별도 A/B 예정)

## 8. 아직 안 된 것

- **곡률은 여전히 잡음** — 원시 중심선 유한차분 `|kappa|` p99 0.379 / max 3.589 1/m.
  L0 의 `kappa_lane` 테이블은 스플라인 적합 없이는 못 만든다. *(별도 진행 중)*
- **L0·L4 의 표현력 천장 89.9%** — 남는 10%는 succ-only 후보가 밴드 안에서 표현 못 하는
  미래이고 ADE 하한으로 남는다. (L3 는 자유 위치 회귀라 이 천장에 안 걸린다)
- **L3 잔여의 정확한 원인 미확정** — 모드 예산 비용이 유력하지만 과소학습 가능성을 못 갈랐다.
- **6초를 못 덮는 시나리오 13.8%** — 6홉으로도 `6·v0 + 20 m` 를 못 채우는 고속 구간.
- **`s_ref = s(1 − kappa_lane·d)` 보정 미적용** — 호길이 조회의 위상 오차. 커브에서
  `0.02 × 1.5 m × 60 m = 1.8 m` 어긋나는데 학습 손실에는 안 보인다.
- **L4 가중치를 1.0 하나만 봤다** — 문서가 "4항 세트는 minFDE 1.86 → 1.99 로 나빠졌다"고
  경고한 만큼 탐색이 필요하다.
- **경로 0개 시나리오(3.75%)의 폴백** — 단계 3·4 학습은 직진 하나만 줘서 그 시나리오가
  사실상 `minADE1` 로 채점됐다(기준선 0.710 → l3b 1.326 — 처음에 1.154 로 적었던 건 l3b 를 부채꼴 데이터로 평가한 방법 오류였다). 이후 부채꼴 호 6개로 바꿨고
  `v4_l3c` 로 검증했고 **실패했다** — 전체 1.416 → 1.424. 두 가지가 같이 나왔다:
  (1) 폴백 버킷의 개선(1.326 → 0.931)은 **채점 인공물**이다. 모드가 1 → 6 이 되어 "6개 중
  최소"를 고르게 된 것뿐이고, 확률 최상위 모드로만 재면 1.326 → **1.420 으로 나빠진다.**
  (2) 진짜 손해는 **입력이 한 바이트도 안 바뀐 나머지 1,925개**에 있다(1.419 → 1.443) —
  train 의 약 3.1% 가 바뀌어 gradient 로 모델 전체를 흔들었다.
  → **국소적으로 이기고 전역적으로 진다.** 기하 탓인지 모드 예산 탓인지 가르려고 직진 경로를
  6슬롯에 복제한 판(`v4_l3d`, 기하 다양성 0)을 돌렸다. 직진 1개 1.414 / 직진 6개 1.409 /
  부채꼴 1.424 로, **세 방식의 차이가 시드 1개의 노이즈 범위라 어느 쪽 탓인지 가를 수 없었다.**
  폴백 기본값은 단계 3·4 재현을 위해 직진 1개로 되돌렸다(`b1db1a6`).
- **θ₀ 가 90° 를 넘는 모드가 기존 규칙에서도 48개 있다** (val 2,000 살아있는 모드의 0.41%).
  경로가 차량 반대쪽을 향하는 경우로, 2.4절의 가드와는 별개 문제다.
- **(a, h) 입력 판에는 5채널 재학습 기준선이 없다** (사용자 결정). 입력·θ₀ 규칙·적분기 기하가
  한꺼번에 바뀌어서 입력 효과를 따로 가를 수 없다.
- **(a, h) 입력의 h 채널은 wrap 이라 시나리오의 1.33% 에서 ±π 점프가 스파이크로 들어간다.** 관측 50스텝을
  시간축으로 이어 붙이고 마지막 스텝만 (−π, π] 로 맞추는 unwrap 이 대안이다(관리 세션 제안, 채널 수는 그대로).
  입력이 바뀌어 재학습이 필요하므로 보류했다.
- **L4 판은 두 입력 모두 요레이트 상한 8°/step 에 붙어 있다** (dθ max 8.00°, 7.3° 초과 3.4~5.2%).
  상한을 라벨 정상값 7.3° 로 낮추면 초과는 사라지지만, 그 정확도 대가는 아직 안 쟀다.
