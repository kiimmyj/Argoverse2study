# v5 — HD map으로 차로 간 이동 가능 규칙 만들기

작업일: 2026-08-27 · 위치: `Argoverse2study/src/` · 상태: 구현·검증 완료, 학습 적용 전

---

## 1. 무엇이 문제였나

현재 `dataset_map.py`는 지도를 이렇게 줌.

```
lanes (20, 10, 2)   focal 근처 차선 20개 × 10점 × (x, y)
```

**좌표뿐임.** 모델 입장에서 이 20개 선은 전부 똑같이 생겼음. 어느 것이 대향차로인지, 넘을 수 없는 실선인지, 애초에 갈 수 없는 곳인지 구분이 안 됨. 역주행하는 예측이 나올 수밖에 없는 구조임.

그런데 **지도는 이미 답을 갖고 있었음.** 안 쓰고 있었을 뿐임.

## 2. AV2 HD map에 실제로 들어있는 것

`log_map_archive_*.json`을 뜯어봄. 차로 하나(`lane_segment`)마다 이만큼 있음.

| 필드 | 내용 | 기존 사용 |
| --- | --- | --- |
| `centerline` | 중심선 | ✅ 이것만 씀 |
| `left/right_lane_boundary` | 좌·우 경계선 (3D) | ❌ |
| `left/right_lane_mark_type` | 차선 표시 종류 | ❌ |
| `lane_type` | VEHICLE / BUS / BIKE | ❌ |
| `is_intersection` | 교차로 내부인가 | ❌ |
| `predecessors` / `successors` | 차로 연결 그래프 | ❌ |
| `left/right_neighbor_id` | 좌·우 인접 차로 | ❌ |

최상위에 `drivable_areas`, `pedestrian_crossings`도 따로 있음.

실측 분포 (val 120 시나리오, 차로 8,030개):

- **차선 표시** — NONE 4,209 / DASHED_WHITE 1,688 / SOLID_WHITE 1,366 / DOUBLE_SOLID_YELLOW 759 …
- **차로 종류** — VEHICLE 3,576 / BIKE 599 / BUS 26
- **교차로** — 내부 1,421 / 외부 2,780

## 3. 결정적 발견 — 인접차로의 45%가 대향차로임

가장 중요한 사실임. `left_neighbor_id`가 **같은 방향 차로만 가리키지 않음.**

| | 쌍 수 | 대향(>135°) 비율 |
| --- | --- | --- |
| `left_neighbor` | 5,174 | **45.2 %** |
| `right_neighbor` | 2,836 | 0.1 % |

우측통행이라 중앙선 건너편 대향차로가 **왼쪽 이웃**으로 잡히기 때문임.

**즉 "인접차로 = 차선변경 가능"으로 두면 좌변경의 절반이 역주행이 됨.**

방향각 분포는 0.3° 아니면 180° 근처로 완전히 갈렸고, **90°~135° 사이에는 표본이 하나도 없었음.** 임계값을 어디에 두든 같은 결과가 나옴.

차선 표시도 이를 뒷받침함.

| | 표시 종류 |
| --- | --- |
| 대향 인접차로 | 노란색 계열 62 % + NONE 38 % |
| 같은 방향 인접차로 | 흰색 계열 80 % + NONE 18 % |

미국 관행대로 **노란색 = 대향 분리, 흰색 = 동일방향 분리**임. 다만 NONE이 양쪽에 다 나와서 **표시만으로는 판별 불가**임. 방향 검사가 1차 근거여야 함.

## 4. 규칙 네 가지

`src/lane_graph.py`에 구현함.

| 이동 | 규칙 |
| --- | --- |
| **SUCC** 진행 | `successors`만 따라감. `predecessors`는 절대 이동으로 쓰지 않음 (= 역주행 금지의 뿌리) |
| **LEFT** 좌변경 | `left_neighbor` 중 **방향이 같고** + 맞닿은 표시를 넘을 수 있는 것만 |
| **RIGHT** 우변경 | `right_neighbor`에 같은 조건 |
| **UTURN** U턴 | 교차로를 최대 3단계 경유해 진행방향이 뒤집히는 경로 |

표시별 통과 여부: 점선 계열 ○ / 실선·이중실선 ✗ / NONE·UNKNOWN ○ (도색이 없는 것이지 막힌 게 아님. 교차로 내부가 대부분)

> U턴을 따로 찾아야 하는 이유: `successors`가 곧장 방향을 뒤집는 경우는 **8,201쌍 중 2건**뿐임. 실제 U턴은 '좌회전 차로 → 교차로 내부 → 반대 방향 본선'처럼 두세 단계로 나뉘어 있음.

## 5. 검증 — 실제 궤적으로 규칙을 시험함

규칙이 옳다면 **focal이 실제로 지나간 미래 차로는 규칙상 도달 가능해야 함.** 너무 느슨하면 도달 집합이 지도 전체가 되고, 너무 빡빡하면 실제로 간 곳을 못 간다고 함. 둘 다 이 지표로 잡힘.

### 첫 결과는 78.2%였음

규칙이 어딘가 과하다는 뜻이었음. 무엇이 원인인지 하나씩 풀어봄.

| 완화 | 적중률 |
| --- | --- |
| 기준 | 78.2 % |
| + SOLID_WHITE 넘기 허용 | 78.2 % |
| + SOLID_DASH도 허용 | 78.8 % |
| **표시 규칙 전부 해제** | 84.9 % |

**표시 규칙은 원인이 아니었음.** 전부 풀어도 85%에서 막힘.

### 진짜 원인은 차로 매칭이었음

실패 사례를 직접 뜯어보니 대부분 **시작 차로가 교차로 안**이었음. 교차로에서는 좌회전·직진·우회전 차로가 공간적으로 겹치는데, **가장 가까운 하나만 고르면 엉뚱한 분기에 갇힘.** 도착점 반경 5m 안에 도달 가능한 차로가 있는데도 다른 걸 골라서 놓치는 경우도 있었음.

차로 매칭을 **후보 집합**으로 바꾸니 해결됨.

| 매칭 방식 | 적중률 |
| --- | --- |
| 시작 1개 / 도착 1개 | 78.2 % |
| 시작 1개 / 도착 반경 5m 전부 | 87.7 % |
| 시작 2개 / 도착 전부 | 93.1 % |
| 시작 3개 / 도착 전부 + 예산 여유 60m | 97.1 % |
| **시작 4개 / 도착 전부 + 예산 여유 60m** | **98.3 %** |

배운 것: **차로 매칭은 본질적으로 애매함.** 하나로 찍으면 안 됨.

## 6. 최종 성능

### 튜닝에 쓴 300개 (판정 257개)

| | 적중률 | 후보 차로 | 지도 대비 | 후보에 섞인 역주행 차로 |
| --- | --- | --- | --- | --- |
| **규칙 적용** | **98.1 %** | 14.4개 | 21.4 % | **1.35개** |
| 규칙 없음 | 99.2 % | 31.5개 | 48.1 % | 12.92개 |

### 처음 보는 400개 (판정 354개) — 과적합 확인

| | 적중률 | 후보 차로 | 역주행 차로 |
| --- | --- | --- | --- |
| **규칙 적용** | **97.7 %** | 15.0개 | **1.63개** |
| 규칙 없음 | — | 30.5개 | 11.85개 |

튜닝 표본(98.1%)과 미사용 표본(97.7%)이 0.4%p 차이라 **상수를 표본에 맞춰 끼워넣은 게 아님.**

**적중률 1%p대만 내주고 후보를 51% 줄이고 역주행 차로를 86% 걷어냄.**

남은 1.6개는 좌회전을 두 번 이어붙이면 반대 방향이 되는 **정상 경로**라 역주행이 아님.

전체에서 규칙에 걸려 잘린 인접 연결: 대향차로 6,076건 / SOLID_WHITE 4,034건 / SOLID_DASH_YELLOW 347건

### 놓친 5건의 원인

각 실패마다 무엇을 풀면 해결되는지 하나씩 시험함.

| 시나리오 | 이동 | 무엇을 풀면 해결되나 |
| --- | --- | --- |
| 00f65fe7 | 28.8 m | **시작 매칭 반경 12m** / 예산 3배 |
| 0119275b | 66.2 m | **시작 매칭 반경 12m** / 표시 규칙 해제 |
| 0193b2be | 24.1 m | **시작 매칭 반경 12m** / predecessors 허용 |
| 01c53999 | 5.3 m | **시작 매칭 반경 12m** / 대향차로 허용 |
| 0300c983 | 26.9 m | **시작 매칭 반경 12m** / 예산 3배 |

**5건 전부 시작 차로 매칭 반경이 원인임.** 후보 개수를 8개로 늘려도 안 되고 반경을 늘려야 해결됨 — 정답 차로가 차량에서 5~12m 떨어져 있었다는 뜻. 교차로처럼 넓은 구간에서 차량이 차로 중심선에서 멀리 있을 때 생김.

다만 반경을 12m로 키우면 미사용 표본에서 97.7% → 98.3%(+0.6%p)에 그치면서 역주행 차로가 1.63 → 2.38개(+46%)로 늘어남. **역주행을 걷어내는 게 목적이므로 5m를 기본값으로 둠.** 재현율이 더 중요하면 `CAND_RADIUS_M`으로 조절.

## 8. 데이터셋 통합

`dataset_lane.py`가 기존 `(20,10,2)` 차선 옆에 **규칙 피처 `(20,10)`** 을 붙임.

```
[0:2] 진행방향 단위벡터 (focal 기준 회전)   ← 역주행 판단의 핵심
[2]   focal 과 같은 방향인가
[3]   교차로 내부인가
[4:7] 차로 종류 (VEHICLE / BUS / BIKE)
[7]   왼쪽으로 차선변경 가능한가
[8]   오른쪽으로 차선변경 가능한가
[9]   규칙상 도달 가능한 차로인가         ← 탐색 공간을 절반으로 줄여주는 신호
```

예측 시점에는 미래 주행거리를 모르므로 **현재 속력 × 6초**로 도달 예산을 잡음.

### 기존 실험과 사과 대 사과인지 확인함

| | 결과 |
| --- | --- |
| 궤적 `x`, `y` | **비트 단위로 동일** |
| 차선 `lanes` 좌표 | 중앙값 3e-5 m, 최대 5e-4 m 차이 (float32 연산 순서) |
| 선택된 차선 집합 | 99.7 % 일치 |

처음에는 53%만 일치했음. 원인이 두 가지였음 — ① 차선 선택 기준(중심점 거리 vs 최단거리), ② 중심선 출처(av2 API가 좌·우 경계선에서 10점으로 재계산 vs JSON 저장값). 둘 다 기존과 맞춤. 개선안은 `select="nearest"` / `centerline="json"` 플래그로 따로 켤 수 있게 둠.

### 속도

| | ms/샘플 |
| --- | --- |
| `dataset_map` (기존) | 34.9 |
| `dataset_lane` (규칙 포함) | **33.8** |

규칙을 얹었는데 오히려 조금 빠름. `ArgoverseStaticMap` 객체를 만들지 않고, 20개를 고른 **뒤에** 리샘플링해서임 (기존은 41개를 전부 리샘플링하고 20개만 씀).
