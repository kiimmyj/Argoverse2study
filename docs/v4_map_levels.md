# v4 부록 — 지도 융합 레벨 L0~L5 레퍼런스

앞 문서에서 "지도를 네 군데에 꽂는다"고만 하고 넘어간 부분을 레벨별로 펼친 것임.
**어디에 · 언제 · 무엇을 결정하는가**로 나눠 봄.

![지도 융합 레벨](../map_levels.png)

---

## 1. 한눈에

```
       [오프라인 전처리]  지도 폴리라인 · 후보경로 K개 · 곡률테이블 · off-road 필드
              │        │        │        │        │
             L1       L2       L3       L0       L4
            (탈락)   (채택)   (채택)   (채택)   (채택)
              ▼        ▼        ▼        ▼        ▼
     ① 인코더입력 → ② 인코더 → ③ 디코더 → ④ 적분기 → ⑤ 손실
                                          ▲
                                         L5 (탈락)
```

**들어가는 시점이 전부 다름.** L1·L2는 예측 전, L3는 예측하는 순간, L0는 궤적 복원 중,
L4는 예측 후 채점 때임. 같은 "지도를 넣는다"라는 말로 뭉뚱그리면 안 되는 이유가 이것임.

## 2. 각 레벨이 무엇인가

| | 무엇을 하나 | 언제 | 무엇이 필요한가 |
| --- | --- | --- | --- |
| **L1** | 과거 50 step에 차선까지 거리·각도차를 붙임 | 입력 만들 때 | 차선 폴리라인 |
| **L2** | 지도를 토큰으로 만들어 차량이 참조 | 인코딩할 때 | 차선 폴리라인 |
| **L3** | 후보 차선 경로 K개가 예측 모드가 됨 | 모드 정할 때 | **경로 열거기** |
| **L0** | `kappa = kappa_lane(s) + delta` | 궤적 복원 중 | **경로별 곡률 테이블** |
| **L4** | 도로 밖으로 나간 만큼 벌점 | 채점할 때 | **off-road 거리장(SDF)** |
| **L5** | 예측 중간에 현재 위치로 지도 재조회 | 복원 루프 안 | 실시간 조회 |

## 3. 무엇이 다른가 — 세 축

### 3.1 지도를 몇 번 보는가

```
L1, L2   예측 시작 전에 한 번        → 60 step 굴러가는 동안 지도를 안 봄
L3, L0   모드 정할 때 + 복원할 때     → rollout 안에서 지도가 살아있음
L4       끝나고 채점할 때
L5       매 step 마다                → 이상적이지만 순환이 생김
```

**앞 문서의 "L2만으로 부족하다"가 여기서 나옴.** 인코더는 "지금 어디 있는가"를 알지만,
30번째 스텝의 위치는 어떤 지도 특징과도 직접 닿지 않음. 오차가 쌓이는 곳은 rollout이지 과거가 아님.

### 3.2 무엇을 결정하는가

| | 결정하는 것 |
| --- | --- |
| L2 | **연속적인 특징** — 주변이 어떻게 생겼는가 |
| L3 | **이산적인 선택** — 좌회전이냐 직진이냐 |
| L0 | 그 선택 안에서의 **출력 기준값** |
| L4 | 예측이 나온 뒤의 **벌점** |

L2와 L3의 차이가 핵심임. **L2는 "갈림길이 둘 있다"고 알려주지만 단일 query는 여전히 평균을 냄.**
다중모드를 만드는 것은 정보가 아니라 **이산 조건 변수**임. 앞 문서의 평균 세탁이 L3로만 잡히는 이유.

### 3.3 어느 모드에 영향을 주는가

WTA 학습에서는 정답에 가장 가까운 하나만 거리 손실을 받음.

```
L2, L3, L0   모든 모드에 똑같이 정보를 줌 → 하지만 gradient 는 승자가 다 가져감
L4           모든 모드에 개별로 벌점을 줌  → 버려진 K-1 개를 감독하는 유일한 것
```

off-road 예측은 사실상 전부 버려진 모드에 있으므로, **L4가 아니면 손댈 방법이 없음.**

## 4. 의존 관계와 구현 순서

```
L2  ─── 독립. 지도 캐시만 있으면 됨          → 1순위
L4  ─── off-road 필드만 있으면 됨           → 2순위
L3  ─┬─ 경로 열거기 필요
     │
L0  ─┘  L3 가 경로를 골라줘야 성립          → 같은 PR
```

**L0는 혼자 못 씀.** 기준 경로를 하나 골라야 하는데, 교차로에서 **경로를 고르는 행위가 곧 모드 결정**임.
하나로 정하면 t=0에 동전을 던지는 셈이라 다중모드가 무너짐.

| 순서 | 무엇 | 전제 |
| --- | --- | --- |
| 1 | **L2** 지도 인코더 + cross-attention | 지도 캐시 |
| 2 | **L4** off-road 손실 (단일 항) | SDF 필드 |
| 3 | **L3 + L0** (같은 PR) | 경로 열거기 + 곡률 테이블 + recall@5 ≥ 0.90 |
| — | ~~L1~~ | 정보 기여 0이라 해제. 유효성 플래그 4채널만 즉석 계산 |
| — | ~~L5~~ | DAG를 깨고, 안정화하면 정보가 사라져 삭제 |

## 5. 왜 둘은 뺐나

**L1** — 붙이려는 값들이 전부 L2 입력에서 **계산해낼 수 있는 값**이라 정보가 0임.
예외는 "여기는 주차장이라 차선이 무의미"라는 유효성 플래그 하나뿐인데, 이건 정보 문제가 아니라
표현 능력 문제임 — **attention 의 softmax 는 항상 1로 합해져서 "볼 게 없다"를 표현하지 못함.**

**L5** — 위치로 조회하면 `위치 → 방향 → 곡률 → 조회 → 위치` 순환이 생겨 **60스텝을 하나씩 돌아야 함.**
앞 문서에서 곡률을 골라 얻은 "누적합 2번" 성질을 통째로 잃음.

게다가 고치려는 두 수정이 서로를 무효화함. 갈림길에서 되먹임이 발산하므로(조금 왼쪽이면 왼쪽 곡률을
읽고 더 왼쪽으로 감) 안정화하려면 조회를 3m 넘게 뭉개야 하는데, **그 폭이 두 분기를 평균내버림.**
갈림길을 도우려던 장치가 정확히 갈림길에서 무력해짐.

## 6. 지금 레포와의 접점

| 레벨 | 현재 상태 |
| --- | --- |
| L2 | `model_map.py` 에 이미 있음 (lane_encoder + MultiheadAttention) |
| L3 | 열거기는 `src/lane_graph.py` 로 **이미 있음**. recall@5 는 아직 안 잼 |
| L0 | 곡률 테이블 없음. 중심선에서 계산하는 전처리 필요 |
| L4 | SDF 없음. `drivable_areas` 폴리곤에서 만들어야 함 |
| 예측 모드 | 현재는 **학습된 익명 슬롯 K=6** — 앞 문서가 지적한 그 방식 |

**가장 먼저 잴 숫자는 L3의 recall@5 임.** 후보 집합에 정답 경로가 없으면 그 차량은 학습으로
넘을 수 없는 천장에 걸림. 0.90 미만이면 L3와 L0를 함께 포기하고 L2 + L4 로 확정함.
열거기가 이미 있어 순수 전처리 측정으로 끝남.
