# v4 액션 설계 문서 — 읽기 해설

원문 「v4 설계 — 두 개의 핵심 결정」의 논리 흐름을 풀어서 정리한 것입니다.

---

## 한 문장으로

**"미래 위치를 찍지 말고 운전 조작을 예측한 다음 물리로 굴리자. 대신 그러면 지도와의 연결이 끊기니, 지도를 네 군데에 다시 꽂아 넣자."**

---

## 1. 근본 아이디어 — 위치 대신 액션

지금 레포의 `model_map.py`는 미래 60스텝의 `(x, y)` 120개를 직접 뱉습니다. 이 문서는 그러지 말자고 합니다.

대신 매 스텝 **스칼라 두 개**만 예측합니다.

```
a       가속도  — 얼마나 밟고 얼마나 브레이크 밟는가
kappa   곡률    — 얼마나 휘는가
```

그리고 **고정된 물리 공식**으로 궤적을 복원합니다. 속도를 적분해 거리를 얻고, 곡률을 적분해 방향을 얻고, 방향을 적분해 위치를 얻습니다.

**왜 이게 좋냐면** — 모델이 무슨 값을 뱉든 나오는 궤적은 **반드시 차가 실제로 실행할 수 있는 것**이 됩니다. 순간이동도, 제자리 90도 회전도 나올 수가 없습니다. 물리 법칙이 손실 함수나 후처리가 아니라 **출력 형식 자체에 박혀 있기 때문**입니다.

문서가 인용한 수치가 이겁니다.

| | 위치 회귀 | 액션 예측 |
| --- | --- | --- |
| 실행 불가능한 궤적 | **26 %** | **0 %** |
| 6초 시점 heading 오차 | 7.69° | 4.92° |

> 여기서 짚을 것: **minADE는 실현가능성을 재지 않습니다.** 정답에 가깝기만 하면 물리적으로 불가능해도 점수가 좋습니다. 예측 결과를 사람이 그림으로 보는 게 아니라 **플래너가 입력으로 받는다면** 실행 불가능한 26%는 치명적입니다.

## 2. 그런데 대가가 있습니다

`(a, kappa)`는 **차 기준 상대량**입니다. "3초 뒤에 0.05만큼 휜다"는 정보만으로는 **그게 지도상 어디인지 알 수 없습니다.**

반면 지도는 **절대 위치에서만 의미가 있습니다.** 차선이 위도경도 어디에 있는지가 지도의 전부니까요.

**이 간극이 문서의 나머지 전부입니다.** 결정 2(지도를 어디에 넣나)는 이 대가를 갚는 작업입니다.

## 3. 왜 하필 곡률인가

"휘는 정도"를 나타내는 후보가 셋 있었습니다.

**조향각이 탈락한 이유** — 핸들 각도에서 궤적을 얻으려면 **축거**(앞뒤 바퀴 축 거리)가 필요한데, 데이터셋은 바운딩 박스만 주고 축거를 안 줍니다. 추정해서 쓰면 모든 라벨에 차종별 오차가 섞입니다.

**yaw rate가 탈락한 이유** — `omega = kappa × v`라 **속도와 엉켜 있습니다.** 같은 코너를 30km/h로 도는 것과 60km/h로 도는 것이 서로 다른 값이 됩니다. 그리고 정지 차량에서 무너집니다 — `v=0`이면 어떤 값을 내도 궤적이 안 변해서 라벨이 무의미해집니다.

**곡률은 순수 기하량**입니다. `kappa = 0.083`이면 회전반경 12m이고, 빠르든 느리든 같은 뜻입니다.

### 진짜 이유는 따로 있습니다

여기가 문서에서 가장 영리한 부분입니다.

> **곡률은 차선 중심선의 곡률과 단위도 의미도 같습니다.**

그래서 지도 융합이 **그냥 덧셈**이 됩니다.

```
kappa = kappa_lane  +  delta
        ─────────      ─────
        지도가 줌       모델이 학습
        "이 차선은      "이 운전자는 차선보다
         여기서 이만큼    얼마나 더/덜 휘는가"
         휜다"
```

조향각이나 yaw rate를 골랐다면 지도 정보를 쓰려고 **학습된 변환기**를 하나 더 붙여야 했을 겁니다. 곡률은 차원이 그냥 맞으니 변환이 필요 없습니다.

그리고 **학습 난이도가 바뀝니다.** 모델이 배울 것이 "이 코너의 절대 곡률"이 아니라 **"차선 대비 잔차"** 가 됩니다. 대부분의 주행에서 잔차는 0 근처의 작은 값이라 문제가 훨씬 쉬워집니다.

> 한 가지 정확히 해두면 — AV2 지도가 곡률을 **저장해서 주지는 않습니다.** 지도 스키마를 확인해 보면 `centerline` 점열만 있고 곡률 필드는 없습니다. 중심선 점들에서 계산해내야 합니다. 문서 표현("공표하는 것과 같은 물리량")도 그 뜻이지만, 오프라인 전처리로 곡률 테이블을 만드는 작업이 별도로 필요합니다.

## 4. 부수 효과 — 계산이 한 방에 끝납니다

곡률을 고르면 계산 순서에 **순환이 없습니다.**

```
a → v → s → kappa → theta → p
```

**곡률이 속도로 되돌아가지 않는 게 핵심**입니다. 그래서 주행거리 `s`가 횡방향 계산과 무관하게 먼저 완성되고, 60스텝 전체의 지도 조회를 **한 번에** 할 수 있습니다.

결과적으로 60스텝 rollout이 **누적합 2번**으로 끝납니다. 한 스텝씩 순차로 도는 루프가 없습니다. 그래서:

- 학습이 빠릅니다
- **exposure bias가 0입니다** — 순차 생성 모델의 고질병(학습 땐 정답을 넣고 추론 땐 자기 예측을 넣어 오차가 눈덩이가 되는 것)이 구조적으로 없습니다. 액션 60개를 한 번에 내고 펼치니 학습 경로와 추론 경로가 같습니다

**이 성질이 나중에 L5를 탈락시키는 근거가 됩니다.**

## 5. 지도를 왜 네 군데에나 넣나 — 각자 다른 병을 고칩니다

| | 하는 일 |
| --- | --- |
| **L2** 인코더 attention | 주변 지도 상황 파악 |
| **L3** 후보 경로 = 예측 모드 | **어느 갈림길로 갈 것인가** |
| **L0** `kappa = kappa_lane + delta` | 그 갈림길이 정해졌을 때의 출력 형식 |
| **L4** off-road 손실 | 버려진 모드 감독 |

### L2만으로는 왜 부족한가

이게 설계의 출발점입니다. 같은 인코더에 헤드만 바꾼 실험이 있습니다.

```
L2형 헤드 (지도는 인코더에만)   off-road 0.069
경로 조건화 헤드                off-road 0.004    → 17배 차이
```

**인코더는 같은 지도를 봤는데** 한쪽이 17배 더 자주 도로 밖으로 나갑니다.

이유가 명쾌합니다. **오차가 쌓이는 곳은 rollout이지 과거가 아닙니다.** 인코더는 "지금 어디 있는가"를 압니다. 그런데 디코더가 60스텝을 굴러가는 동안 **아무도 지도를 다시 안 봅니다.** 30번째 스텝의 위치는 어떤 지도 정보와도 직접 닿지 않습니다.

**"지도를 인코더에 넣는다고 디코더가 지도를 아는 게 아니다."** 이게 나머지 셋이 필요한 이유입니다.

## 6. 가장 중요한 부분 — 평균 세탁

문서에서 제일 미묘하고 제일 중요한 대목입니다.

T자 교차로에서 좌회전과 직진이 반반이라고 합시다. 모델이 모드 구분 없이 학습되면 **액션의 평균**을 뱉습니다.

```
좌회전   kappa = 0.083   (반경 12 m)
직진     kappa = 0
평균     kappa = 0.0415  (반경 24 m)
```

이 평균 곡률로 20m를 가면 방향이 48도 꺾이고, 횡가속도는 6.0 m/s²로 **마찰 한계 8 안쪽**입니다.

**즉 모든 검사를 통과합니다.** 곡률이 상수라 매끄럽고, 물리적으로 실행 가능하고, 속도도 정상입니다. **그런데 이 궤적은 교차로를 48도로 비스듬히 가로질러 반대편 중앙분리대로 들어갑니다.** 아무도 안 하는 주행입니다.

> **적분기가 평균을 그럴듯함으로 세탁합니다.**
>
> 위치를 직접 회귀했다면 같은 평균이 **눈에 띄게 찌그러진 부채꼴**로 나타나서 그림 한 장이면 잡힙니다. 그런데 **액션 공간에서는 볼 게 없습니다.** 꺾임도 없고, 비현실성도 없고, 경고도 없습니다.

이건 **액션 파라미터화를 고른 대가**이고, L3만이 고칠 수 있습니다.

- **L2는 못 고칩니다** — "갈림길이 둘 있다"고 알려줘도 단일 query는 여전히 평균을 냅니다. 다중모드를 만드는 건 정보가 아니라 **이산 조건 변수**입니다
- **L4도 못 고칩니다** — 큰 교차로는 폴리곤 전체가 주행 가능이라 이 궤적에 벌점이 0입니다

**그래서 L3(후보 경로를 예측 모드로 삼기)가 대체 불가입니다.** 모드가 학습된 익명 슬롯이 아니라 지도에서 실제로 열거된 경로여야 합니다.

지금 레포의 `model_map.py`가 딱 그 "익명 슬롯 K=6" 방식입니다.

## 7. L0는 L3 없이는 성립하지 않습니다

`kappa = kappa_lane + delta`를 쓰려면 **기준 경로를 하나 골라야** 합니다. 그런데 교차로에서 **기준 경로를 고르는 행위가 곧 모드 결정**입니다.

경로를 하나로 정해버리면 t=0에 동전을 던지는 셈이고 다중모드가 무너집니다. 그래서 문서가 이렇게 못 박습니다.

> **"L3를 안 지으면 L0를 짓지 마라. 둘은 같은 PR에 들어가야 한다."**

### 여기 숨은 함정 하나

`kappa_lane`을 조회할 때 쓰는 거리 `s`는 **차가 실제 달린 거리**인데, 지도의 곡률 테이블은 **중심선 기준 거리**로 인덱싱돼 있습니다. 차가 중심선에서 옆으로 벗어난 채 커브를 돌면 두 거리가 어긋납니다.

```
오차 = kappa_lane × d × s = 0.02 × 1.5m × 60m = 1.80 m
→ 회전 구간에서 heading이 4.13도 틀어지고
→ 남은 40m에서 횡오차 2.9 m
보정: s_ref = s × (1 - kappa_lane × d)   ← 곱셈 한 번
```

**학습 손실에는 안 보입니다.** 안 고치면 "가끔 커브에서 이상한 궤적이 나오는데 원인을 모르겠다"에 갇힙니다.

## 8. L4는 왜 필요한가 — 버려진 모드

다중모드 학습의 표준인 **WTA(승자독식)** 는 K개 예측 중 **정답에 가장 가까운 하나에만** 손실을 겁니다. 나머지 K−1개는 **gradient를 전혀 못 받습니다.**

그리고 off-road 예측은 사실상 전부 그 **버려진 모드들**에 있습니다. L2·L3·L0을 아무리 잘 넣어도 이건 안 고쳐집니다 — 그것들은 모든 모드에 똑같이 정보를 주고, gradient 예산은 승자가 다 가져가니까요.

**단, 한 항만 씁니다.** off-road 손실을 4항 세트로 다 넣은 실험은 `minFDE 1.86 → 1.99`로 오히려 나빠졌습니다.

그리고 **"안쪽일수록 좋다"로 쓰면 안 됩니다.** 주행 가능 폴리곤의 중심축은 편도 2차선 도로에서 **정확히 중앙 이중황색선**이라, 세게 걸면 정면충돌 차선을 최적해로 학습합니다. **밖으로 나갔을 때만 벌주는 단측 hinge**여야 합니다.

## 9. 왜 둘은 뺐나

**L1 (인코더 입력에 차선 상대좌표 붙이기)** — 그 값들이 전부 L2 입력에서 **계산해낼 수 있는 값**이라 정보가 0입니다. 다만 예외 하나 — "여기는 주차장이라 차선이 무의미하다"는 유효성 플래그는 남깁니다. **attention의 softmax는 항상 1로 합해져서 "볼 게 없다"를 표현할 수가 없기 때문**입니다. 정보 문제가 아니라 표현 능력 문제입니다.

**L5 (rollout 중간에 지도 재조회)** — 두 가지가 각각 치명적입니다.

첫째, 위치로 조회하면 **4절의 DAG가 깨집니다.** 위치→방향→곡률→조회결과→위치로 순환이 생겨 60스텝을 하나씩 돌아야 합니다. 속도와 exposure bias 이점을 전부 잃습니다.

둘째, **고치려는 두 수정이 서로를 무효화합니다.** 갈림길에서 이 되먹임은 발산합니다(조금 왼쪽에 있으면 왼쪽 곡률을 읽고, 그래서 더 왼쪽으로 갑니다). 안정화하려면 조회를 3m 넘게 뭉개야 하는데 **그 폭이 두 분기를 평균내버립니다.** 갈림길에서 정보를 주려고 넣은 장치가 정확히 갈림길에서 정보를 지웁니다.

## 10. 정직하게 밝힌 약점

문서가 스스로 인정하는 부분이고, 가장 중요한 대목입니다.

**AV2 리더보드 상위권(QCNet, MTR++, Wayformer)은 전부 위치를 직접 회귀하고 액션 공간 지도 융합이 0입니다.** 이 설계로 상위권에 간 사례가 없습니다.

| 사는 것 | 파는 것 |
| --- | --- |
| 실현가능성 26% → 0% | minADE 약간 |
| heading 7.69° → 4.92° | (Frenet 계열 A/B는 주 지표에서 음수) |
| off-road 17배 개선 사례 | |

**그래서 타당성이 목적에 달려 있습니다.** 다운스트림이 플래너면 이 거래가 맞고, 리더보드 순위가 목표면 다른 선택이 낫습니다.

## 11. 그래서 뭘 먼저 하나

문서가 제시한 순서에서 **협상 불가라고 표시한 것 두 개**가 핵심입니다.

**0단계 — waypoint 헤드 대조군.** 같은 인코더 위에 위치 헤드와 액션 헤드를 나란히 학습시켜 비교. **이 문서의 논증 전체가 이 A/B 하나로 무효화될 수 있으므로** 본격 구현 전에 확인합니다.

**0.5단계 — 레짐별 평가 슬라이스.** 이 문서가 다룬 실패(평균 세탁, 호길이 위상 오차, 버려진 모드의 off-road)가 **전부 집계 minADE에는 안 보입니다.** 슬라이스 없이는 채택/기각 판단 자체가 성립하지 않습니다.

**3단계 선행 확인 — 후보 경로 recall@5 ≥ 0.90.** 후보 집합에 정답 경로가 없으면 그 차량은 **학습으로 넘을 수 없는 천장**에 걸립니다. 0.90 미만이면 L3와 L0를 함께 포기하고 L2 + L4로 확정합니다.

| L3 선행 확인 (recall@5) | 아직 안 잼. 열거기가 있어 몇 분이면 측정 가능 |

| 예측 모드 K=6 | 현재는 **학습된 익명 슬롯** — 문서가 지적한 그 방식 |
| 출력 파라미터화 | 현재는 **위치 직접 회귀** |
| off-road 손실 / SDF | 없음 |

> 참고: 레포의 `docs/v4_motion_representation.md` 는 **입력** 표현을 `(v, a, heading)` 으로 바꾸는 실험이고,
> 이 문서는 **출력** 을 `(a, kappa)` 액션으로 바꾸는 설계입니다. 서로 다른 작업인데 둘 다 v4 번호를 쓰고 있어
> 문서를 정리할 때 번호를 나누는 편이 좋습니다.
